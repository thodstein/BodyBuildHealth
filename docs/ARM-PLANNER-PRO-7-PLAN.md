# ARM PRO-7 — план и границы (закрыт)

Продолжение `ARM-PLANNER-PRO-6-AUDIT-PLAN.md`. PRO-6 закрыла engine-level контракты
(экспорт-guard, provenance, annual `armPlan`). PRO-7 закрывает оставшиеся разрывы
между «движок умеет» и «пользователь видит и может применить».

Коммит: `68d7ee3e8` (26 файлов движков/UI/тестов + 10 движков единого tendon-источника).
Без пуша.

## 1. Что закрыто

### P1 — адаптивность

- **Готовность к нагрузке** (`data-arm="pro7-card"`): ACWR считается из sRPE-сессий
  дневника (`loadSRPESessions` + `acuteChronicRatio`), затем `assessArmReadiness`
  (sRPE/боль/ACWR) и `resolveArmReturnToLoad` (фаза hold → isometric → low_load →
  build → return → load, `maxLoadPct`, `minRir`).
- Честная граница в UI: сигналы **не меняют план автоматически** — объём/веса
  меняются на шаге «План» или через правки.

### P2 — контуры

- **Rulebook UI** (`arm-rulebook-panel.tsx`): WAF 2025 eligibility (без выдуманного
  взвешивания — при отсутствии веса «нужна проверка»), Armlifting USA 2026 —
  протоколы снарядов, стратегия попыток, симуляция месяца. Каждое правило —
  versioned snapshot с источником.
- **Аннотации к упражнениям** (`arm-annotations.engine.ts` + панель): заметка или
  ссылка на видео с привязкой «неделя · сессия · упражнение», кап 60, строки уходят
  в печать плана.
- **Импорт результатов соревнований** (`arm-result-import.engine.ts`): CSV
  (`снаряд,попытка,вес,результат`) и JSON (`{date, implement, attempts[]}`) →
  журнал помоста с датой соревнования. Неизвестный снаряд блокирует импорт целиком;
  нераспознанные веса/результаты отбрасываются с предупреждением; `;`/tab имеют
  приоритет над запятой, чтобы `55,5` не разрывалось.
- **Diff вариантов**: к неделям/сетам/фазам/помышечным дельтам добавлены веса
  верхнего сета, средний RIR и состав упражнений (только A / только B / в обоих).

## 2. Осознанно не сделано (границы)

1. **Coach/team workflow — не реализован.** Требуется мультиатлетская модель данных
   (несколько спортсменов, права, история решений тренера), а не ещё одна карточка.
   Это продуктовое решение, а не пробел PRO-7; реализация потребует отдельного плана
   и согласования (иначе получится half-feature без прав доступа).
2. **Видео-аннотации — только ссылка/имя файла**, без загрузки и разбора: в APK
   офлайн-сценарий, файловое хранилище видео не спроектировано. Существующий
   видео-контур хаба (`arm-video-analysis`, `armlift-video-flags`) не дублируется.
3. **Импорт результатов не парсит PDF/фото протоколов** — только текстовые форматы,
   которые organizers отдают файлом. OCR протокола — отдельная задача.
4. **ACWR берётся из sRPE-дневника**, а не из замеров помоста: разные шкалы, смешивать
   нельзя. При пустом дневнике сигнал не показывается (тихо, без нулей).
5. **Весовая категория не подбирается автоматически** (PRO-6, остаётся в силе):
   автовыбор класса противоречит правилам взвешивания.
6. **Банный штанговый VBT для grip не внедрялся** — нет измерительного контракта
   для силовых качеств в этом виде спорта.

## 4. Инцидент раунда (зафиксирован для истории)

Перезапись `ArmAutoConstructor.tsx` через PowerShell склеила файл в одну строку
(2325 строк → 1). Восстановление: бэкап в temp, затем `git show HEAD:<path>` +
Write и повторное применение всех PRO-7-хуков через Edit-инструмент, сверка
`git diff --numstat` и полный прогон тестов. Урок подтверждён: **контент файлов —
только Edit/Write-инструмент**, PowerShell-rewriting недопустим (BOM + CRLF +
потеря разделителей строк). Для частичного коммита смешанного файла применена
процедура `HEAD + мои ханки → hash-object -w → update-index --cacheinfo`.
