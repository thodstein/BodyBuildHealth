## 2. Очередь работ

Порядок — по соотношению «эффект / риск». Каждый пункт: где, что сделать, чем мерить, какой замок, что может сломаться.

### P1-1. Ручной канон 2 % не применяется к флагу «в допуске» и к рецептурному пути (S)

- **Где (строки — до правки, §8.135):** `meal-plan-engine.ts:28556` (`withinTolerance: _dayDevPctP4 <= PLANNER_CONVERGENCE_PCT`), `planner-recipe-mode.ts:2310` и `:4863` (`devOut <= 3`); плюс ноты вердикта, печатавшие «канон 3 %» на любом пути.
- **Дефект:** ручной день на 2.4 % помечен «в допуске», хотя §8.122/§8.115/§8.108/§8.128 уже судят его по 2 %. Пользователь видит зелёную точность при нарушенном каноне своего пути.
- **Сделать:** один предикат канона по пути (`kbjuMode === 'manual' || manualTargetsLocked ? 2 : PLANNER_CONVERGENCE_PCT`) в трёх точках; прокинуть его в рецептурный контур, а не дублировать.
- **Мерить:** ручные дни 2.0–2.5 % сетки — флаг обязан стать `false`; число дней «в допуске» до/после.
- **Замок:** новый кейс в `planner-manual-convergence-and-veg-gate.test.ts` (ручной день 2.4 % → `withinTolerance === false`, авто 2.4 % → `true`).
- **Риск:** UI-подписи «Точность рациона» (§8.129) покажут больше красного на ручном пути — это честно, но проверить тексты нот.

### P1-2. Овощной пол: остаток 9 ручных дней — физика тарелки, лечится upstream (L)

- **Где:** композиция приёма (бюджеты/веса приёмов, `CARB_W`, `distributeCarbsByCapacity`), НЕ финальный добор §8.122.
- **Дефект:** приёмы приходят в финал с 660–700 г твёрдого, комнаты под овощ 0–4 г. Адресно: `p500/*/отд` 72 г, `keto85` 63–100 г, `mass110/*/отд` 185 г, `normal90/3/отд` и `recomp80/3/отд` 180 г / 1 вид.
- **Сделать:** резерв 150–200 г тарелки под овощ на этапе распределения углеводов (мейн с овощем получает меньше крупы), либо квоту овоща в бюджете приёма. Отвергнутое не повторять: «резерв 40 г в доборе», «добор без среза крахмала», «пол среза 50/60 г» (замер §8.122).
- **Мерить:** овощ <200 г (9 → 0), один вид (9 →), «вёдра» в классе, тарелки >700 г, `maxDry`, балл качества.
- **Замок:** `planner-veg-floor-8122` (пороги **не** поднимать: ручной ≤9 / ≤1 / ≤9, авто ≤0 / ≤1), `planner-veg-topup-note-8122`.
- **Риск:** резерв тарелки отнимает место у крупы → день перестаёт сходиться по У; приёмка — по канону 2 %/3 %.

### P2-1. Микро-ось в `preferVegPlan122`: гейт качества её не видит (M)

- **Где:** `meal-plan-engine.ts:7831–7907`.
- **Дефект:** балл плеч считается `scoreDayQuality(p.meals, { weightKg })` без `microCoverage`, а `qualityScore.total` плана микро учитывает. Овощное плечо может быть выбрано при падении `qualityScore.total` (один лишний low-nutrient = −8.75 по оси ≈ −1.05 итога).
- **Сделать:** считать микро каждого плеча из ЕГО финальных позиций (`sumMicros` + `analyzeMicroCoverage` + `lowCountForScore`, как `_qNow` в `23837`) и передавать в `scoreDayQuality` симметрично обоим плечам.
- **Мерить:** A/B 160 дней — `qualityScore.total` овощного плеча ≥ честного на каждом дне, где овощной план выбран.
- **Замок:** новый кейс в `planner-veg-floor-8122` (выбранный план не ниже по `qualityScore.total`, чем альтернатива — снять оба плеча через флаг `vegTopUp88: false`).
- **Риск:** регрессия `small60` (микро-вес 60/кг) — держать `planner-microrole-veg`.

## 3. Харнесс замера (обязателен для каждого шага)

Один прогон — 160 дней (§1). Метрики считать теми же функциями, что в замках:

- канон по осям: `maxDeviationPct` (авто 3 % / руч 2 %);
- обрезки: пол роли (`MIN_MEANINGFUL_G`) + `_fixedGrams` не считаются;
- овощ: `isRealVegItem` (`planner-quality-score.ts:69`) — роль `veg`, белок < 12 г/100 г, микро-флаги ВХОДЯТ;
- «вёдра»: абсолютное (>1.35 × доли дня) и в классе (мейны с мейнами, перекусы с перекусами);
- «не еда»: белок приёма < 20 г при крахмале ≥ 100 г;
- тарелки: твёрдое (без `liquid`) >500 / >700 / >900 г;
- `maxDry`: максимальный пункт сухой крупы;
- балл: `scoreDayQuality(meals, { weightKg, microCoverage })` — с микро, как `qualityScore` плана.
