## 1. Интернет-синтез (проверено фетчем)

1. **ISSN Position Stand: Nutrient Timing (Kerksick 2017, JISSN 14:33)** — гликоген
   максимизируется при **8–12 г/кг/сут**; при <4 ч до следующей сессии — агрессивный рефид
   **1.2 г/кг/ч**; во время длительной (>60–70 мин) работы — **30–60 г У/ч** раствором 6–8%;
   белок **20–40 г каждые 3 ч**; казеин **30–40 г** перед сном. Вывод: 1500 г У — это
   легитимный суперкомпенсационный/инсулин-режим, но кормить его надо **распределённо и
   жидкостями**, а не тарелками по 700 г.
2. **ISSN Position Stand: Protein and Exercise (Jäger 2017, JISSN 14:20)** — 1.4–2.0 г/кг
   достаточно; >3.0 г/кг может иметь смысл на дефиците; **0.25 г/кг или 20–40 г на порцию**,
   лейцин 700–3000 мг, **равномерно каждые 3–4 ч**; распределение важнее пиков. Вывод: 500 г на
   110–120 кг = 4.2–4.5 г/кг — выше любого потолка доказательности (честный warning уже есть);
   но при таком объёме **порция 40–68 г × 10–12 приёмов** — единственный реальный способ.
3. **Физиология ЖКТ (Gastrointestinal physiology / gastric emptying)** — жиры (CCK) и
   объём замедляют опорожнение, GLP-1 замедляет его; «тарелка 700 г еды» — уже верх
   практической переносимости; сверх этого нужны **жидкие калории, дробность и низкий жир**.
   Вывод: капы тарелки должны расти **только на инсулине и при явном запросе**, а разницу
   закрывать напитками/пюре и числом приёмов, а не одной тарелкой.
4. **Клинические правила инсулина** — «правило 500»: **10 г быстрых углеводов на 1 ЕД**
   болюса; коррекция и еда согласуются, 40 ЕД одним болюсом = ~400 г У, которые физически
   нельзя съесть одной порцией → в практике **split-бол/пролонгированный болюс + 2–4 приёма
   в окне 2–4 ч**. Вывод: окно движка должно быть **цепочкой 2–4 под-кормлений ≤120 г** и
   честной рекомендацией разделить укол/использовать пролонг (не меняя дозу пользователя).
5. **Вода/электролиты** (следствие 1 + объём еды): при 8000+ ккал и 120 ЕД/сут потеря Na/K с
   потом и мочой выше; ориентир «5–6 л воды, Na 4–6 г, K ≥3:1 к Na» — в движке сейчас
   только generic-совет.

## 3. План доработки (эпики A–J)

Порядок: **P0-ядро A → B → C → D → E**, затем P1 F–H, P2 I–J. Один эпик = один коммит
pathspec своих файлов + прогон области IndividualPlan (база 99 файлов / 991 тест, сейчас 0
падений) + re-baseline только с числом «было→стало». Обычные дни (≤4000 ккал, без инсулина)
— **байт-в-байт**.

### A. Capacity scaling под инсулин/массу (ядро, P0-3/P0-6)
- NEW чистый `extremeCapacityProfile(input)` в `planner-carb-density.ts` (или рядом):
  `{ plateMult, snackCarbCap, dryGrainCap, itemCap, edibilityMult, recipePlate, drinkBudget }`
  от `insulinUnits`, `carbs/weight`, `kcal`:
  - `plate`: 700 → **900** (мейны) / 750 → 850 (снеки) при `insulin>0 || carbs/weight ≥ 6.5`;
  - `snackCarbCap`: 120 → **150** (6–8 г/кг) → **180** (≥8 г/кг или болюс);
  - `dryGrainCap`: 170 → **200/240**; `EDIBILITY` rice 450→**600**, cream 400→**550**,
    bread 165→**220**, potato 300→**400** (множитель только в extreme-профиле);
  - `itemCap`: 600 → **800**; `recipePlate`: 730 → **900**.
- Применение: во всех точках капов (передать профиль в `mealCarbCapacityG`, `maxDryGrainPerMeal`,
  `carbPortionCap`, `buildWholeMeal`, `distributeCarbsByCapacity`, `plateRoom`).
- Гейт: профиль активен только на HV/инсулин-дне (иначе 1.0). `carbCapGPerKg` не трогаем.
- **Приёмка:** 1500У/120кг/3×40 ЕД → ≤ **12** приёмов (сейчас 16), макс тарелка ≤900,
  сходимость У ≤3%, нет нот «добавьте приём» на train; без инсулина 1500У → У ≥99% (сейчас 97.3%).

### B. Диетический таймлайн приёмов (P0-2)
- NEW `distributeMealTimes({count, wake, bed, trainStart, trainDuration, insulinTimes, isTrainingDay})` —
  единая сетка: мейны/снеки с мин. интервалом **2.5–3 ч** (снек ≥2 ч), peri фиксированы
  (prew/intra/postw), insulin-окна по времени укола, pre-sleep от отхода.
- Collision-guard: два независимых приёма не ближе 30 мин (окно+его приём — можно);
  при нехватке окна времени — честный note «не влезает, добавьте +1 час ко дню/уберите приём».
- Заменить шаблонные `_snackTimeOf` (только для сгенерированных снеков; prew/postw/intra/окна
  сохраняют свои времена).
- **Приёмка:** нет двух приёмов <30 мин (кроме окно+сосед); интервалы мейнов 3–5 ч;
  окно ≤15 мин от укола; snapshot существующих калиброванных дней — только при явном
  улучшении (иначе гейт по `highVolumeDay`).

### C. Инсулин-окно v2 «цепочка» + честный advisory (P0-1, P1-13)
- `windowChainForBolus(dose, meals, times)`: `need = clamp(dose*10, 30, 400)`;
  разбить на под-кормления по **≤120 г У** в окне ±90 мин (укол + соседние мейны),
  каждому — свой носитель из ротации `[cream_of_rice, rice_white, bread_white, orange_juice, dextrose]`
  (с учётом sugar-share 15/20/25%).
- Если соседний мейн уже несёт ≥need×0.8 — окно-топ-ап не создаём (паритет с текущим
  поведением, но с учётом цепи по обоим соседям).
- Advisory при `dose ≥ 25 ЕД`: «разделите болюс (2×dose/2 с интервалом 2–4 ч) и/или
  пролонгированный болюс; держите быстрые У (декстроза) для гипо».
- **Приёмка:** 3×40 ЕД → потребность каждого болюса покрыта ≥90% суммой окна+соседей; ни одно
  под-кормление >120 г; окна разных болюсов не дублируют один id; закрытие окон от коррекций
  сохранено (`_insulinWindow`-инвариант).

### D. Финальные инварианты капов (P0-4)
- `enforceExtremeCaps(meals, profile)` — **один финальный проход** ПОСЛЕ P4/P5b/P6/P7,
  корректора и рецептурного добора: EDIBILITY×profile, COMFORT, CONCENTRATE 50, FRUIT 150,
  plate ≤ profile, item ≤ profile.
- При нарушении: перенос в приём с комнатой → иначе честная нота и срез до капа
  (jam 215→35/80, rice 522→600 (профиль) и т.п.).
- **Приёмка:** ни один item/тарелка не превышают профиль; рецептурный ужин ≤900;
  guard-тест «финальный проход существует и стоит последним».

### E. Рецептурный экстрим v2 (P0-5)
- Компонентный скейл карбов уже есть (`scaleComponentAmount`); довести до всех мейнов:
  выбор рецепта по **carb-room** (скоринг «сколько У рецепт даёт в цель приёма», а не только
  kcal-дистанция), сайды приоритетно в мейны с carb-дефицитом.
- **Anti-thrash**: в `rebalanceDayAfterRecipes` — память шагов, запрет циклов A→B→A,
  сворачивание логов в одну строку «ребаланс: N корректировок» (сейчас 20+ строк).
- Не ломать ядра — но при переборе **белка ядер** честно писать «эффективная цель Б = X» и
  предлагать пользователю пересмотреть цель (сейчас молча +22–27%).
- **Приёмка:** рецептурный 1500У dev ≤ **12%** (сейчас 26.7/18.2), Б ≤ +10% цели,
  нот-циклов нет, снеки без «изолят+изюм ×3» (≥3 разных носителя).

### F. Честность выдачи (P1 7–10, 11, 16)
- Точность: сравнивать с ЦЕЛЬЮ пользователя; если внутренняя — показывать обе строки
  («к цели 280: +22% (эффективная 342 — полы приёмов)»).
- VitD-нота: единицы IU/мкг согласовать; вычистить «+500 мкг».
- UL: Mg/Zn — только для добавок (или не применять к еде); Na — «ориентир», не «предел»
  (пометка источника).
- Лейбл MPS-снека — по `isTrainingDay`.
- «Сумма болюсов 120 ЕД (3×40)».
- **Приёмка:** в дампах нет «+500 мкг», нет Mg-избытка на еде, лейбл корректен, точность
  согласована с целью.

### G. Разнообразие на экстриме (P1-12)
- Расширить `DENSE_CARB_LADDER` напитками (соки/морсы/декстроза/изотоник/молоко);
  ротация носителей окон и мейнов (id ≤2 приёма, кроме исключений);
  белок-ротация (turkey 3× → рыба/говядина/курица/яйца/морепродукты).
- **Приёмка:** 1500У → ≥6 разных карб-носителей, окна без повторов id, белок ≤3 приёма на id.

### H. Вода и электролиты для больших дней (P1-14)
- `waterTarget = 35 мл/кг + 400–500 мл/1000 ккал сверх 3000 (+пот)`; Na/K-ориентиры под
  инсулин/пот; вывод в карточку дня и в брифинг; связать с `waterCalc`/MetabolicHub.
