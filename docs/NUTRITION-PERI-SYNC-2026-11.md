# Пери-воркаут ⇄ рацион: синк по кнопке, «мясо и рыба», соль по приёмам (2026-11)

Короткая памятка по механике, которую добавили в планировщик питания. Полная
история аудитов — в `NUTRITION-PLANNER-QUALITY-AUDIT-2026-10.md`; здесь только
контракты и точки правки.

## 1. Один бюджет пери-окон

Раньше на один вопрос «сколько углеводов до/после тренировки» было два ответа:

- карточка «Пери-воркаут» считала `computePeriWorkoutNutrition()` от последней
  **завершённой** сессии;
- движок рациона раскладывал углеводы по своим долям (`CARB_W`, капы 60/75).

Пользователь видел 120 г на вкладке и 40 г в рационе. Теперь бюджет считается
**один раз** в `planner-peri-budget.ts`, а карточка, настройки и движок читают его же.

| Константа | Значение | Смысл |
|---|---|---|
| `PERI_CAP_PRE_CARB_G` | 60 | ёмкость окна «до» (= `mealCarbCapacityG('prew')`) |
| `PERI_CAP_POST_CARB_G` | 75 | ёмкость окна «после» |
| интра | 40 г/ч, 30–90 г | `intraWindowCapacityG()` = формула движка `mealCarbCapacityG('intra')` |
| `PERI_MIN/MAX_POST_PROTEIN_G` | 12–60 | белок пост-трена |

`recommended` хранит желание протокола ДО капов, `capped` — сработал ли кап
(включая интра). Карточка показывает бюджет окна, рядом — «в окно влезает до N г».

## 2. Синхронизация с планом тренировок — только по кнопке

- Тумблер планировщика «Синхронизация с пери-воркаут» (`plannerPrefs.periSync`)
  разрешает **потребление** бюджета; сам бюджет появляется только после нажатия
  «🔄 Взять из плана тренировок».
- Источник — `planner-planned-tonnage.ts`: `he_pl_runtime` → день недели →
  подходы с весом×повторы → тоннаж; длительность = 3 мин/подход + 12 (20–150);
  интенсивность по числу подходов/длительности. Фолбэк — последняя сессия.
- Состояние синка — ключ `he_peri_sync` (athlete-level, НЕ `DEVICE_LEVEL`:
  иначе данные одного атлета покажутся другому; см. `data-space-key-guard`).
- «План перегенерили» определяется подписью (`planSignature()` — fnv1a по
  `days`): подпись в синке ≠ текущая → предупреждение «синхронизируйте заново».
- Кнопка в карточке сразу пишет `periSync: true` в prefs и пересобирает рацион;
  в контексте это подхватывается событием `he:peri-sync` и ref (`periSyncRef`),
  потому что state к моменту вызова `generatePlan` ещё не обновился.

## 3. Инвариант: дневные суммы не меняются

Бюджет окон **перераспределяет** углеводы, а не добавляет их:

- окно получает `min(бюджет, ёмкость)`;
- разница переносится в основные приёмы пропорционально их весам (пол приёма 35 г);
- после округлений сумма дня выравнивается до исходной (`_carbsForRoles`).

Поэтому сходимость КБЖУ ≤3% не задевается. То же для белка: `periProteinFixed`
считается как «остальные части пери-бюджета + фактические окна», пост-трен берёт
`postProteinG` из бюджета, дневная цель белка остаётся прежней.

Путь строго гейтится: без `input.periBudget` движок работает байт-в-байт как
раньше (старые вызовы и тесты не меняются).

## 4. Режим белка «мясо и рыба» (мягкий)

- `proteinSourceMode: 'meat_fish'` + `proteinAnchors` (по умолчанию
  `['salmon','beef_lean']`, список — `PROTEIN_ANCHOR_OPTIONS`).
- В `buildWholeMeal` обед/ужин начинают выбор белка с якорей; если выбранный
  источник — порошок/молочка/соя, он заменяется на flesh из пула доступных
  продуктов (якоря → весь flesh-пул → ничего, день не ломается).
- Завтрак и перекусы не трогаем: яйца/творог/сыворотка там уместны (MPS-типология).
- Вегетарианская диета сильнее режима — режим молча отключается.
- В нотах дня — фактическая доля белка из мяса/рыбы в главных приёмах
  (ориентир ≥60%, ниже — предупреждение).

## 5. Соль/натрий по приёмам

- `planner-meal-sodium.ts`: Na позиции (`item.na` → фолбэк FOOD_DB через
  `planner-micro-reader.getMicroFromFood`), сумма приёма, сумма дня.
- Единицы: **1 г NaCl = 400 мг Na**, то есть `соль_г = Na_мг × 2.5 / 1000`.
  В UI показываем оба числа: «🧂 1.84 г соли · Na 736 мг».
- Чип рисуется в каждом приёме. Если натрия нет ни в одной позиции — честная
  приглушённая плашка «нет данных о соли», а не ложный ноль и не пустое место.
- `na` пишется движком в `makeItem`, переносится в сохранённый план и
  масштабируется во всех правках порций/склейках позиций (ключ добавлен в
  массивы `['p','f','c','kcal','fiber','leucine_mg','na']`).
- Дневная строка «Соль за день» — в блоке «ИТОГО ЗА ДЕНЬ», цвет по доле от
  2300 мг Na (35% / 50%).

## 6. Проверки

- `planner-peri-sync.test.ts` — 22 кейса: тоннаж из плана, подпись, капы,
  ёмкость интра-окна, равенство «бюджет ↔ движок», матрица профилей (60/90 кг,
  день отдыха) на канон 3%, flesh-режим и его отключение при вегетарианстве,
  суммы натрия и обязательная плашка соли.
- `npm run type-check`, `npm run verify:apk-design` — обязательны.
