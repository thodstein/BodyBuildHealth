# Периодизация питания — профессиональный модуль планировщика (Oct 1 2026)

## 0. Контекст

Планировщик питания (`src/ui/screens/NutritionScreen_parts/IndividualPlan/`) уже
профессиональный на уровне **движка дня**: единая целевая арифметика (`buildDayTargets`),
карб-периодизация (`applyCarbPeriodizationMods`), контест-преп
(`nutritionTargetsForPrepDate`), MPS/лейцин, пери-окружение, микро/электролиты,
рецептурный путь, отчёты, экспорт. Аудит (Sep 2026, волны E14–E16) свёл экстремумы
HV1500/500Б ≤3%, peri-полы к LBM-шкале, клетчатку ≤85 г.

**Единственный крупный профессиональный пробел:** движок умеет считать цели на
**конкретную дату**, но пользователю/тренеру показывался только «сегодня». Не было
**периодизации вперёд** — неделя за неделей (фазы препа → taper → peak → post-show),
день за днём (тренировка/отдых, тяжёлый день, рефид, diet-break, читмил, фастинг) с
фактическими целями КБЖУ/воды/натрия/калия и **целевым весом**. Именно этот слой
превращает набор дней в управляемый профессиональный план.

## 1. Что добавлено

### 1.1 Движок `planner-nutrition-periodization.engine.ts` (чистый, тестируемый)

Фасад над уже существующими канонами — ничего не считает «по-своему»:

- **prep-режим** (есть `BBContestPrepPlan`): каждый день через
  `nutritionTargetsForPrepDate` (подготовка/финальная подготовка/taper/пик/post-show),
  метки `isRefeed`/`isDietBreak` из `isPrepRefeedDay`/`isPrepDietBreakDay`, пик —
  по фазе `peak_week`.
- **general-режим** (нет препа): цель + `applyCarbPeriodizationMods` + тяжёлый день —
  **та же арифметика**, что `IndividualPlanContext.buildOneDay` (показано = сгенерируется).
- **запланированные спец-дни** (`he_special_meals`): refeed ×1.12/×2.2, cheat kcal ≥×1.12,
  fast ≤×0.75/×0.7 — те же моды, что в генерации.
- **целевой вес** (prep): старт × (1 − темп%/нед)^нед по неделям подготовки; taper/пик
  держат stage-вес; post-show — null (кривая восстановления — домен препа).
- Агрегация по неделям (средние КБЖУ/вода/Na/K, счётчики тренировок/рефидов/брейков/пика).
- `prepPeriodizationHorizon(plan)` — горизонт «весь преп» = подготовка + taper + пик + 12 нед post-show.

Экспорт: `buildNutritionPeriodization`, `prepPeriodizationHorizon`, `weekdayIndexForIso`,
`PERIODIZATION_GOAL_RU`, `PERIODIZATION_HORIZON_OPTIONS`, типы `PeriodizationDay/Week/Input/Base`.

### 1.2 UI `NutritionPeriodizationCard.tsx`

Карточка «🍽 Периодизация питания» (вставлена в таб «План» после разбора дня, перед
выбором дней):

- шапка: режим (🏁 Контест-преп / 🎯 цель), карб-периодизация, дата шоу;
- сводка-чипы: тренировки, недели подготовки/taper, рефиды, diet-break, пик;
- горизонт: 1/4/8/12 нед + «🏁 Весь преп» (prep), печать;
- таблица недель (фаза с цветом, Ккал, Б/Ж/У, 🎯вес, вода, Na, метки 🏋️/🔄/🍔/⏳/🏖/🎭);
- клик по неделе → дни недели (день недели, тренировка/отдых/тяжёлый, цели, метки);
- заметки (движок препа / diet-break / периодизация);
- `data-*` хуки: `data-periodization`, `data-mode`, `data-horizon`, `data-horizon-btn`,
  `data-periodization-weeks`, `data-week`, `data-day`, `data-periodization-summary/-notes/-print`;
- печать HTML (XSS-esc) с полной таблицей дней.

Мемоизация по **значениям** (sig-строка) — не пересчитывается на каждый рендер родителя.

### 1.3 Проводка

- `IndividualPlanContext`: `bbPrepPlan` добавлен в `PlanCtx` (ctx + deps) — единый план
  препа доступен поверхностям (раньше был только внутренним state).
- `IndividualPlanResults`: карточка рендерится при `generated && effectiveKcal > 0`;
  база (ккал/Б/Ж/У + вода/натрий из `waterCalc`), график тренировок
  (`buildTrainSchedule`/`isTrainingDayFor`), `he_special_meals`.

## 3. Осознанные границы

- В prep-режиме вода/натрий дня = канон генерации (3000 / `PREP_SODIUM_BASE_MG`), иначе
  «показано ≠ сгенерировано»; в general-режиме — из `waterCalc`.
- Спец-дни календаря в prep-режиме показаны **метками** (цели фазы задаёт prep-движок,
  как и в живом рационе) — моды применяются в general-режиме.
- Целевой вес — расчётная траектория по темпу препа, не факт из дневника (сравнение с
  фактом — существующий «📊 План vs Факт» и чек-ин препа).
- Карточка живёт в табе «План»; отдельная вкладка не добавлялась (dense-таб без правок
  shared-навигации).

## 4. E17 (Oct 1 2026): чистая выдача + вес-факт + таб

- **Вес-факт** (п.2 §4 — ВЫПОЛНЕНО): движок принимает `weightLog`, считает средний вес недели и
  дельту к цели; карточка показывает `🎯цель / ⚖️факт ±Δ` (зелёный ниже цели / янтарный выше).
- **Отдельный таб «🍽 Периодизация»** (п.1 §4 — ВЫПОЛНЕНО): в секции «Анализ» `NutritionScreen`,
  `NutritionPeriodizationTab` (обёртка над той же карточкой) + `nutrition-periodization-tab` тест.
- **Чистая выдача рациона** (запрос «без свалок»):
  - время приёмов кратно 5 мин (`gapFillTimes`);
  - EAA/изотоник — фикс-доза (было EAA 12→165 г в intra);
  - поздний перекус (после 20:00) — без завтрак-стейпла/десерта (слот `lateSnack` + гварды
    density-swap/У-добора + финальный санитайзер с компенсацией Б/Ж, guard «не навреди»);
  - финальное сглаживание ultraP (500Б): главные приёмы ≤ цель×1.35.
  - Lock: `planner-clean-ration-e17` 4/4.
- **Границы**: «1500У/220Б» (низкий белок на 1500 г углеводов) — честный best-effort с флагом;
  канон HV1500 (500Б+1500У) сходится ≤1%. Микро-наполнители (лайм/урбеч) в обычных перекусах —
  малые флейвор-порции, не «свалка».

## 6. E20 (Oct 1 2026): недельный разбор

- **`planner-weekly-review.engine` + `WeeklyReviewCard`** (§6 п.1 — ВЫПОЛНЕНО): приверженность
  (±5%), средние КБЖУ за окно, тренд веса (%/нед против целевого темпа по цели), вердикт
  on_track/too_slow/too_fast, **одна** рекомендация ±150 ккал; <4 дней логов → no_data.
  Разбор советует, а не применяет (смена ккал — решение пользователя).
- Разнообразие овощей/жиров внутри дня — проверено пробой (повторов нет) → не требуется.

## 7. E20-добивка (Oct 1 2026)

- **Кнопка «Применить ±150 ккал»** (§7 п.1 — ВЫПОЛНЕНО): `applyKcalAdjust` переводит план в ручной
  режим КБЖУ с новой калорийностью (белок сохранён, жиры/углеводы масштабируются) + тост.
- **PRO-гейт `planner-goal-realism`** 5/5: mass/cut/recomp/maint/F60 — точность ≤3%, без мусора,
  без фрагментных мейнов, off-slot на ночь запрещён, сухие порции ≤260 г, белок в основных приёмах.

## 8. E21 (Oct 1 2026): календарь рефидов/диет-брейков

- **`planner-refeed-calendar.engine` + `RefeedCalendarCard`** (§8 п.1 — ВЫПОЛНЕНО): для сушки/рекомпа

  «📅 В календарь» пишет даты в `he_special_meals` (применится при генерации), печать.

## 9. E22 (Oct 1 2026): добавки в план-лист + Отчёт + диет-брейк + плато

- **Добавки из калькулятора поддержки в план-листе** (`NutritionProCards`/`MealListRender`):
  строка «💊 К приёму» под каждым приёмом (слот через `suppSlotForMealType`).
- **PRO-карточки в табе «Отчёт»** (`NutritionProCards`): периодизация/рефиды/разбор/добавки.
- **Авто-коррекция в режиме НАБОРА**: `applyKcalAdjust` правит профицит % (не manual) для bulk.
- **Полноценная неделя на поддержании**: спец-день `diet_break` (калории к TDEE, углеводы выше),
  «В календарь» пишет 7 дней.
- **28-дневный тренд + плато** в недельном разборе → совет рефид/диет-брейк.
