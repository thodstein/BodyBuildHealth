# План: «Проведение тренировки + дневник» до уровня PRO APK

> Дата: 2026-10-17. Область: `src/ui/screens/TrainingScreen_parts` (дневник/выполнение), `src/ui/screens/SRCBBScreen_parts/SessionPlayer.tsx`, `src/engines/workout-logger.engine.ts`, `src/engines/strength-diary.engine.ts`, Android-виджеты `android/.../widgets/*`.

## 0. Цель и критерии готовности (DoD)

**Главная цель:** одно надёжное, «про-уровневое» проведение тренировки в зале (live-сессия) + дневник, который честно отражает факт, работает офлайн и на APK, и виджеты на домашнем экране телефона.

DoD (всё должно быть зелёным):

1. `npm run type-check` — 0 ошибок.
2. `npm test` — все тесты зелёные (включая `workout-exec-pro`, `workout-diary-audit`, `strength-diary`).
3. `npm run verify:apk-design` — OK.
4. APK-сборка (`npm run build:native`) проходит, виджеты монтируются.
5. Проведение тренировки: один источник логирования (SessionPlayer), без дублей/UTC-дат/RPE=7 по умолчанию.
6. Виджеты: тренировка (живой прогресс + «+ Сет»/«▶ Начать»), таймер (пресеты 30/60/90/180), питание, приверженность — синхронизированы с приложением.
7. Офлайн: все звуки/вибрации локальные, нет внешних URL; Wake Lock; автосейв живой сессии.

## 1. Что уже сделано (база)

- Единый плеер `SessionPlayer` (фазы: ready → warmup → main → cooldown → done).
- `ExecutionZone` больше не ведёт свой «ручной» учёт; адаптер `playerDayFromMicro`.
- Живая сессия: `saveActiveSession/loadActiveSession/summarizeActiveSession`, автосейв, продолжение, «+ Сет».
- Дневник: `StrengthDiary` единый слой IDB+localStorage, дедуп `findDuplicateWorkouts`, write-back.
- Виджеты APK: Training (прогресс+действие+deep-link), Timer (автономный), Compliance, Nutrition.
- APK-маркер-гейт и native-слой CSS.

## 3. План проведения тренировки (UX проф-приложения)

Целевой поток (как Strong/Hevy/JEFIT, но под наш движок):

1. **Старт**: с домашнего экрана виджет «Тренировка» → deep-link `training_run` → `ExecutionZone` → выбор дня (сегодня подсвечен) → «Старт».
2. **Разминка**: персональная (суставы/активация/подводящие), чек-боксы, таймер на каждый пункт (автозавершение), «Пропустить с причиной» (попап, не select).
3. **Основная**: карточка упражнения (название, группа, техника-подсказка), целевые сеты (вес/повторы/RIR/темп), ввод факта (stepper ±), кнопка «Записать подход» (44px), автотаймер отдыха, прогресс-бар упражнения, сравнение с прошлой сессией (Δ вес/повторы).
4. **Заминка**: растяжка, таймер, «Пропустить с причиной».
5. **Итог**: тоннаж, КПШ, e1RM, Δ vs прошлая, рекомендации двойной прогрессии, делод-флаг, RIR-калибровка, sRPE, сохранение в дневник, пуш виджета «готово».
6. **Живая сессия**: при сворачивании/закрытии — автосейв; при возврате — баннер «Продолжить» с прогрессом.

UI-требования про-уровня:
- Минимальные тап-таргеты 44px (уже в тестах).
- Haptic на запись подхода/завершение таймера.
- Wake Lock во время main/cooldown.
- Офлайн-звук (Web Audio).
- Нативные контролы только через попап-шиты (без `<select>` в APK-слоях).
- Большие цифры таймера, прогресс-кольцо, контраст.

## 5. Виджеты на экран телефона (APK)

### 5.1 Текущие

- **Тренировка** (training): живая сессия (прогресс %, «Идёт», «+ Сет») / последняя сессия / «▶ Начать»; deep-link `training_run`/`training_quick`.
- **Таймер** (timer): автономный AlarmManager, пресеты 30/60/90/180, старт/пауза/сброс.
- **Питание** (nutrition): ккал/белок/вода.
- **Приверженность** (compliance): % выполнения плана недели.

### 5.2 План расширения

1. **Синхронизация таймера виджета ↔ сессия**: при старте подхода в приложении — пушить `durationSec=restSec` в виджет-таймер (через `widgetTimerCommand('preset', restSec)`), чтобы виджет показывал тот же отдых. При завершении — «Готово!» + вибрация.
2. **Виджет «Быстрый сет» (1×1 or 2×1)**: одна кнопка «+ Сет» → `training_quick` → приложение записывает подход плановыми весами (уже реализовано) + toast.
3. **Виджет «Сегодня» (2×2)**: план дня (название + число упражнений + прогресс), тап → проведение.
4. **Виджет «Неделя» (4×2)**: 7-дневная полоска выполненных тренировок (как в календаре), тап → дневник.
5. **Виджет «Вода» (1×1)**: быстрая добавка 250мл (уже очередь есть) → `queueWaterMl`.
6. **Обновление**: при возврате из фона `syncAllWidgets()` (уже); добавить WorkManager-периодику (каждые 15 мин) для живого прогресса даже если приложение не открыто (требует native-код).
7. **Pin widget**: UI-кнопка «Закрепить виджет» через `requestPinWidget` (уже API) — добавить в `WidgetsSetupCard`.
8. **Тёмная/светлая тема виджета**: следовать `he_apk_theme_v1` (уже частично), проверить контраст.

### 5.3 Контракт данных виджета тренировки (расширить)

Добавить в `TrainingWidgetInput` и `WidgetStore`:
- `nextExercise` (строка) — следующее упражнение в живой сессии.
- `restRemainingSec` (число) — оставшийся отдых (для виджета-таймера).
- `weekProgress` (0..100) — % выполнения плана недели.
- `lastSessionDate`, `lastSessionVolume`.

## 9. Риски

- **Регрессия тестов**: монолит SessionPlayer — любой рефакторинг рискует сломать 37 тестов `workout-exec-pro`. Делать по шагам, прогонять тесты после каждого шага.
- **APK-гейт**: добавление native `<select>` в тренировочном слое может сломать будущий гейт (сейчас гейтит только кардио/бои). Лучше сразу соблюдать правило.
- **Производительность**: Web Audio + Wake Lock + автосейв на каждом подходе — нагрузка на слабых устройствах. Дебаунс обязателен.
- **Совместимость данных**: миграции localStorage должны быть обратно совместимы (не терять историю).
