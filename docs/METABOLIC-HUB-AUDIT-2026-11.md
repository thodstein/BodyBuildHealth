# Метаболика Pro — аудит хаба калькуляторов (ноябрь 2026)

Файлы: `src/ui/screens/Shared/MetabolicHub.tsx`, `src/ui/screens/Shared/metabolic-hub.parts.tsx`,
`src/engines/metabolic-hub.engine.ts`.

Цель аудита: найти функции, которые не работали или работали неверно, починить их и собрать
UI в понятную структуру (мастер ввода → результаты → действия), не потеряв ни один из 16
калькуляторов.

---

## 1. Что было сломано (причина → исправление)

### 1.1 Вода завышалась почти вдвое

**Причина.** `calcWater` прибавлял к СУТОЧНОЙ норме НЕДЕЛЬНЫЙ объём пота:
`trainingDays × 1.15` часов × 600 мл/ч. При 4 тренировках по часу это +2.3 л/сут
(83 кг: норма выходила ~6.0 л вместо ~3.4 л).
**Исправление.** Недельный пот делится на 7 (`weeklySweatMl / 7`), электролиты считаются
на одну тренировку (`sessionSweatMl`). В `breakdown` добавлены `weeklySweatMl`/`sessionSweatMl`,
чтобы это было видно в UI.
**Регрессия.** `metabolic-hub.test.ts` → «недельный пот делится на 7», «электролиты на сессию».

### 1.2 EA (RED-S) считалась по недельному EEE

**Причина.** UI передавал в `calcEnergyAvailability` недельный EEE (тренировки + кардио за
неделю) как суточный. EA = (EI − EEE)/FFM, поэтому у почти любого активного человека
получалась «LEA red».
**Исправление.** `eeeDaily = weeklyEee / 7`; движок сам применяет ×0.85 (net, Loucks).
**Регрессия.** `metabolic-hub.test.ts` → «calcEnergyAvailability трактует eeeKcal как СУТОЧНЫЙ EEE».

### 1.3 Фиктивные значения в лабораторных полях

**Причина.** Поля рисовались как `value={hct ?? 45}`, `ferritin ?? 120`, `gfr ?? 95`,
`ft4 ?? 17`, `glucose ?? 90`, `insulin ?? 8`, `hdl ?? 50`, `AST/ALT 25`, `тромбоциты 250`,
`JP3 30`, `Durnin 40`, `BIA 500`, `SFA 25`, `ТГ 120`, `GGT 25`, `дефицит 500`, `недель 4`,
`потеряно 2`, `RMR 0`, `EDE-Q 0`. Пользователь видел число, которого движок НЕ считал
(внутри было `undefined`), и зона здоровья выглядела сломанной.
**Исправление.** Новый примитив `MhNum` с честным состоянием «не задано» (opt-in `optional`)
для всех опциональных лаб и замеров. Обязательные поля (вес/рост/возраст/шея/талия) остались
на `PopupNumber`.
**Регрессия.** `metabolic-hub-structure.test.tsx` → «HCT по умолчанию не задан», «опциональные
лабы подписаны «не задано»».

### 1.4 Автообновление лаб из профиля откатывало ручной ввод

**Причина.** `refreshLabs` каждые 8 секунд читал профиль и перезаписывал HDL/AST/ALT/PLT/ТГ/
глюкозу значениями из профиля, даже если пользователь ввёл свои.
**Исправление.** Значения читаются из `valuesRef`, а поля, введённые руками, помечаются в
`manualLabsRef` (`markManualLab`) и авто-refresh их не трогает. Кнопка «Сброс лаб» чистит
пометки (`resetLabs`).

Побочная находка: в `valuesRef` ключи были длинными (`hdlMgDl`, `tgMgDl2`, `glucoseMgDl`,
`insulinMuMl`), а `apply(...)` искал короткие (`hdl`, `tg`, `glucose`, `insulin`) — защита
«не затираем уже показанное» для этих четырёх лаб не срабатывала. Ключи сведены к коротким,
`markManualLab` теперь стоит на всех 13 лабах (hct/hgb/ferritin/gfr/hdl/ast/alt/plt/tg/
glucose/insulin/tsh/ft4).
**Регрессия.** `metabolic-hub-structure.test.tsx` → «ключи `valuesRef` совпадают с ключами
`apply(...)`», «каждая лаба помечена `markManualLab`», «Сброс лаб вызывает `resetLabs`».

### 1.5 Кнопка «Донация сегодня» ничего не сохраняла

**Причина.** `recordDonation`/`recordHct` были мёртвым кодом — журнал не писалеся.
**Исправление.** Пишут в `he_hct_history_v1` и `he_donation_log_v1`, показывают историю HCT
(до 14 точек) и прогноз −4% через 7 дней с пометкой `est: true` (оценка, не измерение).

### 1.6 Сценарии теряли беременность и лактацию

**Причина.** `saveScenario` сохранял только антропометрию и цель, `loadScenario` не
восстанавливал триместр/лактацию → EA и вода считались как «нет беременности».
**Исправление.** Снапшот сценария расширен (триместр, лактация, замеры, цель, дефицит),
загрузка восстанавливает всё. Diff подписывается человеческими названиями (`SNAP_LABEL`),
а не camelCase-ключами.

### 1.7 Билый цвет графика EMA

**Причина.** `fill="rgba(34,197,94,0.15}"` — невалидный CSS, заливка выпадала.
**Исправление.** График переписан как чистый SVG в `metabolic-hub.parts.tsx` (`MhEmaChart`).

### 1.8 Селектор калькуляторов не держался при скролле

**Причина.** `position: 'static'` — 16 пилюль уезжали вверх, приходилось возвращаться.
**Исправление.** `position: 'sticky'` + группы (Энергия / Тело и вода / Питание / Здоровье),
все 16 пилюль остаются в DOM (скрыты `display:none`) — guard-тест на 16 `.mh-mode` цел.

### 1.9 Мастер без навигации

**Причина.** Поля ввода шли одной стеной, без шагов и порядка.
**Исправление.** 4 шага: Тело → Активность → Лабы → Цель. Кнопки «Назад/Далее», сегменты с
`aria-current`, блок «Чего не хватает» ведёт в нужный шаг (`go(mode, step)`).

### 1.10 `lbmPres` считал дефицит от урезанного TDEE

**Причина.** Использовался `kbju.nat.tdee` — он уже содержит goal-delta, то есть дефицит
считался дважды.
**Исправление.** Единый `effectiveDeficit`, `stepsCalc.tdeeNat` как настоящий TDEE для
`at`/`atRange`/`goalV2`/`reverseAuto`.

### 1.11 `MhTile` смешивала `border` и `borderLeft`

**Причина.** Активная плитка задавала шорткат `border` поверх базового `borderLeft`. React
предупреждал «Updating a style property during rerender (border) when a conflicting property is
set (borderLeft)», и рамка могла залипнуть при переключении active → не active.
**Исправление.** Плитка задаёт только длинные свойства (`borderTopWidth/…Color`,
`borderLeftWidth: 3`), без шортката.
**Регрессия.** Предупреждение исчезло из прогона `metabolic-hub-modes.test.tsx` (консоль чистая).

### 1.12 Режимы не проверялись на «реально показывает результат»

**Причина.** Guard-тесты фиксировали структуру (16 пилюль в DOM), но не то, что КАЖДЫЙ режим
реально показывает результат. Сломанный режим (потерянный вход, деление на 0) прошёл бы мимо.
**Исправление.** Добавлен `metabolic-hub-modes.test.tsx`: кликает все 16 пилюль и требует
непустой результат без `NaN`/`undefined`/`null`, плюс что переключение режима не сбрасывает шаг
мастера.

### 1.13 Потолок углеводов съедал цель по калориям (сушка ≈ масса)

**Причина.** `c = clamp(c, 90, weight*5)` — всё, что «не влезло» в потолок углеводов,
молча вычиталось из итога. При TDEE 3659 ккал (83 кг) угли упирались в 415 г, и «сушка»,
«поддержание» и «масса» выдавали почти одинаковые ~3000 ккал: **цель не влияла на план**
(3659 → факт 3031, 4025 → факт 2999). Пользователь выбирал «массу» и получал поддержание.
**Исправление.** Новая чистая функция `balanceCarbsAndFat`: угли ограничены санитарным
потолком (7 г/кг нат, 8 — ААС, 8/9 при high-volume), недобор закрывается жиром до 1.5 г/кг,
а если цель всё равно недостижима — это честно возвращается как `macroGap` (`gapKcal` + текст)
и показывается в плитке КБЖУ (`⚖️ цель −N`) и в блоке режима.
**Регрессия.** `metabolic-hub.test.ts` → «цель по ккал достигается: сушка < поддержание <
масса», «недобор цели подписан честно»; `metabolic-hub-wiring.test.tsx` → «цель: сушка <
поддержание < масса».

### 1.14 Waterfall TDEE подписывал ложное равенство

**Причина.** Подпись «TDEE {kbju.nat.tdee} = BMR + NEAT + EAT + TEF» врала дважды:
`kbju.nat.tdee` уже содержит дельту цели (−455 на сушке), а TEF по собственному же тексту
«сидит внутри PAL». На сушке сумма частей давала 3659 при подписи «3000 = …», то есть
пользователь видел «недобор», которого нет.
**Исправление.** Шкала и подпись строятся от `stepsCalc.tdeeNat` (расход без дельты цели);
в сумму входят только BMR + NEAT + EAT, а TEF подписан как отдельная информация и «в сумму
выше не входит»; рядом печатается план на цель и разница.
**Регрессия.** `metabolic-hub-honesty.test.ts` → «waterfall TDEE: сумма BMR+NEAT+EAT не
выдаёт себя за расход с TEF и целью» (покрывает и режим «Шаги», где было то же равенство;
там сумма частей отличается от TDEE на 1% из-за округления NEAT — теперь подписано `≈` и Δ).

### 1.15 «Бытовая активность» была мёртвым полем

**Причина.** `getEffectivePal` брал базу PAL из профессии, а профессия по умолчанию стояла
`'sedentary'` и была задана всегда → **переключатель «Бытовая» не влиял ни на что** (ни на
TDEE, ни на КБЖУ). Пользователь менял «Низкая/Средняя/Высокая» и не видел ни одной цифры
в ответ.
**Исправление.** В селект профессии добавлен вариант «Не указана → по бытовой» (`'auto'`),
`getEffectivePal`/`calcPALPro` трактуют его как отсутствие профессии (база берётся из
«бытовой»). Под полями появилась честная подпись: профессия и «бытовая» описывают один и тот
же день, поэтому считается только одна, и профессия перекрывает бытовую.
**Регрессия.** `metabolic-hub-wiring.test.tsx` → «бытовая активность реально работает, когда
профессия не указана» (TDEE растёт/падает) и «профессия перекрывает бытовую — и это сказано
текстом»; `metabolic-hub.test.ts` → `getEffectivePal` с `profession:'auto'`.

### 1.16 «Целевых недель» ничего не считало

**Причина.** `weeksToGoal` сохранялся в снапшот/сценарии, показывался в шаге 4 — и не входил ни
в один расчёт. Пользователь ставил «12 недель» и не получал ни проверки, ни дефицита.
**Исправление.** Новая функция `calcDeadlineFeasibility` сравнивает требуемый темп
(`(вес − цель)/срок`) с темпом плана (`дефицит × 7 / плотность кг`, `energyDensityPerKg`):
вердикты `met` / `on-track` / `too-slow` / `too-fast` / `wrong-direction`, плюс сколько ккал не
хватает, в какой срок реально уложится план и предупреждение, если темп выше 1%/нед (похудение)
или 0.5%/нед (набор). Вердикт печатается в шаге 4 цветной строкой.
**Регрессия.** `metabolic-hub.test.ts` → «срок до цели реально проверяется: медленный план,
быстрый, встречный» (плюс `null` без срока/цели); `metabolic-hub-wiring.test.tsx` →
«„Целевых недель“ реально проверяет срок».

### 1.17 Измеренный пот-тест не попадал в воду

**Причина.** Пот-тест считал `sweatV2.rateLPerH` (1.30 л/ч «измеренный»), но в `input` для
`calcWater` уходил ручной `sweatRate` (600 мл/ч по умолчанию). Тест «взвешивание до/после»
показывал 1.30 л/ч, а норма воды считалась по 600, и переключатель «Взвешивание / Оценка»
менял только карточку теста. Акклиматизация (−40% Na, Periard) тоже действовала в тесте, но не
в воде.
**Исправление.** `sweatV2` считается до общего `input`; в воду уходит `effectiveSweatMlPerH`
(измеренное значение, если тест измеренный, иначе ручное) и `effectiveSweatNaMgPerL`
(с акклиматизацией). В шаге 2 появилась строка «💧 В воду идёт N мл/ч — измерено пот-тестом /
ручное значение · Na …», подсказка поля «Пот, мл/ч» объясняет, когда ручное значение в силе.
**Регрессия.** `metabolic-hub-wiring.test.tsx` → «измеренный пот-тест попадает в воду, а не
живёт только в карточке» (переключение режима меняет плитку воды и подпись источника).

### 1.18 EEE из тоннажа завышался в ~5 раз (ложная «LEA red»)

**Причина.** `weeklyVolumeTons * 380`, где 380 ккал — стоимость ОДНОЙ тренировки, а не тонны.
При 20 т/нед это 7600 ккал/нед (1086 ккал/сут) вместо реальных ~1600, и EA уходила в «LEA red»
почти у всех, кто вводил тоннаж. Физика: 1 кг на ~0.5 м ≈ 0.05 ккал работы, КПД ~25% → ~0.1
ккал/кг, то есть 5-тонная тренировка ≈ 60 мин силовой ≈ 400 ккал ≈ 80 ккал/т.
**Исправление.** Одна функция `weeklyExerciseEnergy` (тоннаж 80 ккал/т ИЛИ сессии×380 +
кардио×7 ккал/мин), результат делится на 7 и уходит в EA; в блоке EA напечатано, откуда взят
EEE. Калибровка согласована: 5 т ≈ 380 ккал ≈ одна сессия.
**Регрессия.** `metabolic-hub.test.ts` → «EEE из тоннажа: 80 ккал/т» (20 т = 1600 ккал/нед,
EA при 2600 ккал не в красной зоне, `none` при пустых данных).

### 1.19 Сценарий хранил 22 поля из ~90 — загрузка и сравнение теряли лабы
**Причина.** `saveScenario` собирал снапшот из 22 «главных» полей (`weight…weightLostKg`), а
`loadScenario` восстанавливал ровно их. Всё остальное — 13 лаб, сон/стресс, климат/влажность, пот,
клетчатка/омега-3, MET-ч, тоннаж, замеры — в сценарий не попадало. Поэтому и diff сценариев
физически не мог показать лабы: их не было в сохранённых данных.
**Исправление.** Восстановление вынесено в `applySnapshot(s, { markLabs })` — одно место правды
для автосохранения v6 и для сценария. `saveScenario` кладёт полный `snapshot` (все ~97 полей),
`loadScenario` применяет его же. Лабы из сценария помечаются как ручные, иначе таймер лаб
(раз в 8 с) перетирал их значением из профиля. Пометки «введено руками» теперь тоже сохраняются
(`manualLabs` в снапшоте) — ручной ввод лабы переживает перезагрузку.
**Регрессия.** `metabolic-hub-wiring.test.tsx` → «сценарий хранит лабы и восстанавливает их».

### 1.20 Diff сценариев не видел переключатели и печатал camelCase
**Причина.** `diffMetabolicSnapshots` сравнивал только `number`/`string`, поэтому булевы
переключатели (ААС, креатин, акклиматизация, режим пот-теста, флаги RED-S) в сравнении не
появлялись вовсе. А подписи `SNAP_LABEL` покрывали 29 из ~90 ключей → в блоке «Δ между
сценариями» всплывали `glucoseMgDl`, `hct`, `useMeasuredSweat`.
**Исправление.** Diff включает булевы и снятые значения (объекты-анкеты по-прежнему не тащит);
`SNAP_LABEL` покрывает все ключи снапшота, значения-перечисления переводятся
(`cut → bulk` стало «Сушка → Масса»), булевы читаются по смыслу («взвешивание», «да/нет»).
**Регрессия.** `metabolic-hub.test.ts` → «diff сценариев видит переключатели»;
`metabolic-hub-structure.test.tsx` → «у каждого поля снапшота есть человеческая подпись».

  «Сравнение методов» с честной подписью «только вес/рост/пол», чтобы не путать с LBM по %жира.

## 3. Новая структура экрана

1. Hero + evidence + ААС-предупреждение.
2. Сводка из 6 плиток (TDEE, вода, КБЖУ, EA, кровь, жир) — каждая ведёт в свой калькулятор.
3. «Чего не хватает» — честный список слепых зон с переходом на нужный шаг.
4. Мастер: сегменты 4 шагов + «Назад/Далее» + подсказка текущего шага.
5. Натурал / ААС — один переключатель на весь хаб.
6. Шаг 1: Тело (вес/рост/возраст/пол/% жира/цель/DIAAS/креатин) → замеры Navy + калипер/BIA +
   липидные входы + проекция тела.
7. Шаг 2: Активность (шаги, тренировки, профессия, MET·ч, пот, климат) → пот-тест → восстановление.
8. Шаг 3: Лабы (щитовидка + HOMA, MetS ATP III, гематокрит, RED-S CAT2).
9. Шаг 4: Цель (cut/maintain/bulk/health, AT-поля, беременность/лактация, бариатрия) + сброс.
10. Дополнительные 6 плиток (шаги, Stress Load, алкоголь, белок, цель, MetS).
11. Дневник 7 дней (факт vs TDEE).
12. Сценарии → sticky-селектор групп → результаты активного режима (16 режимов).
13. Действия + `<details>` с источниками.

## 5. Что осталось открытым

- **Углеводный потолок**: теперь санитарный (7/8 г/кг) и цель побеждает его, но выбор именно
  7 г/кг — практический ориентир (ISSN допускает до 12 г/кг на загрузке), не порог из RCT.
- **Тоннаж → ккал для EEE**: теперь 80 ккал/т (калибровано к «5 т ≈ одна сессия ≈ 400 ккал»),
  но это всё ещё оценка — точное значение даёт только измеренный пот-тест/adaptive v3.
  В блоке EA печатается, откуда взят EEE.
- **Stress Load** — по-прежнему эвристика E (не кортизол), подписано в UI.
- **ААС-модель** экспериментальна (Bhasin): +2 кг воды, не +12%.
- **Профессия и «бытовая»** описывают один и тот же день — считается одна (профессия
  перекрывает бытовую, подписано под полями; вариант «Не указана» возвращает бытовую в работу).
  `calcSteps` и `calcPALPro` берут базу из одного правила; остаточное расхождение PALpro ↔ PAL
  вызвано тем, что PRO-обёртка по-другому складывает шаги/стоя, и остаётся подписанным, а не
  спрятанным.
