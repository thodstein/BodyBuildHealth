# Планировщик питания — режимы + V2-скоринг: аудит и план (Aug 19 2026)

Сводный документ по результатам полного критического анализа и тестирования всех режимов
планировщика питания и действующего V2-скоринга. Реализованные исправления отражены в коде,
план доработки и перечень новых функций — ниже для последующих раундов.

## 1. Режимы планировщика: pro / simple / minimal

Реализовано и проверено (эта область):
- `PlannerMode = 'pro' | 'simple' | 'minimal'` (types.ts), persist `he_planner_mode`.
- `quality: 'full' | 'basic'` в `MealPlanInput`; модульный `_qualityMode` в meal-plan-engine
  (синхронная генерация, сброс в finally).
- Pro: полный V2-функционал. Simple: без quality-weighted pick, бюджетного фильтра по
  bb_quality_score, микроанализа (coverage: []), MPS/micro-заметок, DIAAS/GL/II и чипа
  «Pro движок», mpsCheck, healthScore=null, calcMealScoreV2/runCalc, NutritionQualityCard,
  отчёта «Качество», рекомендаций V2, продвинутого/таргетинг-компоновщика.
- Minimal: ранний компактный рендер Settings-вкладки (вес/рост/возраст/пол/цель/приёмы +
  КБЖУ-карточка).
- Обходной фикс мемоизации: `renderMealList = useRenderMealList({ ...ctx, plannerMode })`,
  `finalCtx = useMemo(..., [ctx, plannerMode, renderMealList])`.

Тестирование: planner-область 229/229 (196 + 29 usefulness-calc + 4 nutrition-v2-audit),
tsc 0, vite build OK.

## 3. План доработки действующего V2-функционала

### P0 — целостность данных
1. **Единый DIAAS-модуль**: `kbju-food-match.engine:calcFoodDIAAS` и V2 `calcDIAAS/calcMealDIAAS`
   расходятся (компоновщик фильтрует по одному числу, скор учитывает другое). В kbju:
   `(a as any).tyrosine_mg` всегда undefined → фен+тир занижен; нет cap 1.5/reliable.
   → один источник + тест паритета «показанный DIAAS = учтённый в скоре».
2. **Дефляция meal-DIAAS**: белок продуктов без амино-профиля идёт в знаменатель,
   аминокислоты — 0 → DIAAS смешанного приёма нечестно низкий. → исключать белок без
   профиля из знаменателя + флаг «неполный».
3. **Распространить safeWeight на входы MealComposer** (граммы из UI-чипов).

### P1 — корректность физиологии
4. **Профильные микро-таргеты** в analyzeDailyDiet/nutrition-quality: сейчас статичные
   (Zn 8, Mg 300, K 3500, VitC 50, Se 50, B2 1, B3 10, цистеин 500). → пол/возраст/фаза;
   женский набор (Fe 18, Ca 1000, D), PED-набор (K/Na/Mg/Cr), prep-набор.
5. **Скор дня**: analyzeDailyDiet не агрегирует скоры приёмов → UI-прогресс качества дня.
6. **Пробел в тестах**: гистамин, антинутриенты, глютатион, электролиты, ammoniaRisk,
   HOMA-IR — matrix-тесты на каждый флаг.
7. **Дублирование DIGEST/DIET_PROFILE** (разные значения veg_fruit 0.78 vs 0.85) — одна константа.

### P2 — UX/консистентность
8. Отчёт дня в печати (скор + флаги + покрытие).
9. Семантика `cortisolRisk` («недостаточно быстрых углеводов post-workout») — пояснение в UI.
10. HOMA-IR в карточке дня.

## 4. Дополнительные функции V2 (новые)

1. Скор дня (1-10) + тренд 7/30 дней, бейдж «качество дня».
2. Покрытие микронутриентов (% от профильных таргетов, ~12 ключевых) + «закрыть дефицит» в компоновщике.
3. Протеин-тайминг: равномерность белка по приёмам — диапазон НЕ фиксированный,
   а по сухой массе (FFM): 0.4-0.55 г/кг FFM на приём (кап ~50 г), минимум лейцин 2.5-3 г/приём;
   25-40 г — лишь ориентир для среднего атлета (70-80 кг). Вердикт «MPS-окна».
4. Окна тренировки (pre/intra/post): скоринг окна с учётом времени приёма.
5. Омега-индекс: абсолютные DHA+EPA (≥250 мг/день), не только соотношение.
6. Интеграция с contest prep: скоринг приёмов по фазам (вода/натрий/карб-моды).
7. Женский модуль: железо/кальций/фаза цикла в дефицитах и подсказках.
8. Вечерний приём vs сон: триптофан/магний/глицин вечером.
9. Variety-скор дня (разнообразие групп продуктов).
10. Гидратация в питании: вода/натрий/калий в дневном отчёте.
11. Сравнение день vs день, детект ухудшения качества на диете.
12. Экспорт дневного/недельного отчёта питания (PDF) со скором и флагами.
