# Планировщик питания — логика приёмов пищи: аудит и В2-скоринг (Aug 20 2026)

Сводный документ по результатам полного критического анализа и тестирования всех режимов
планировщика питания. Фокус — **логика планирования приёмов пищи** (продуктовые пулы по
ролям приёмов, тайминг, количество приёмов, пери-тренировочные приёмы, порции, авто-коррекция,
UI таймлайна).

Реализация — отдельными раундами по приоритетам ниже. Этот документ — план (В2-скоринг) и
перечень доработок/новых функций.

## 2. Критический анализ: что реально происходит в логике приёмов

### 2.1 Завтрак/обед/ужин тянут из ОДНОГО продуктового пула — подтверждено
`meal-plan-engine.ts:1362 / 1385 / 1477` — **все три приёма собираются одной и той же функцией
`buildWholeMeal`** и берут продукты из **общих** пулов `buildFoodPools` (уникальный набор только
по *макро-ролям*: `proteinSolid`, `carbSlow`, `carbFast`, `fats`, `vegGreen/Color`, `carbFruit`).

Различия между приёмами сейчас — только:
- доля углеводов по весам `CARB_W` (завтрак 1.0 / обед 1.7 / ужин 0.7) — `:1271`;
- флаги `includeVeg / includeFruit` (завтрак: фрукт да, обед: нет, ужин: нет);
- `vegColorIdx` (цветовая ротация овощей);
- `proteinRotationIds` (ротация белков);
- `preferredByMeal` (только если пользователь вручную задал «любимый» продукт для «Завтрак»).

**Вывод:** при дефолте завтрак может получить ту же гречку/рис + курицу, что и ужин —
«обеденный стол». Никакой продуктовой типологии приёмов (завтрак = каши/хлопья/манка/банан/
ягоды/сухофрукты; ужин = белок + овощи + жиры) нет. Это корень жалобы №1/№8/№10.

### 2.2 Портция «280 г каши в одном приёме» — подтверждено, но это следствие малочисленности приёмов
В движке есть кап `maxGrainPerMeal` = 280 г (350 г на max) — `:166`; `carbPortionCap` `:174`.
Проблема не в капе, а в том, что **при малом `mealsCount` весь дневной запас углеводов
концентрируется в 2-3 приёма** (веса `CARB_W` нормируются только по фактически построенным
приёмам — `:1293`). При 3-4 приёмах на `buildWholeMeal` приходит `carbG` настолько большой, что
порция упирается в кап 280 г, **и авто-коррекция не может добить углеводную цель** — «места
куда впихнуть продукты нет». Это и есть корень жалоб №2 и №7 (авто-коррекция «не работает»).

### 2.3 Тайминг приёмов — нет логики «N часов между приёмами» — подтверждено
- Время приёмов задаётся **жёстко**: завтрак `wakeTime+30`, обед `lunchTime`, ужин `dinnerTime`
  (Context:2283-2298); предтрен `trainStart−90`, пост-трен `trainStart+60`, интра `trainStart+30`
  (`meal-plan-engine.ts:1448/1460/1468`).
- После сборки приёмы просто **сортируются по времени** (`:1569`). **Нет перепланировщика, который
  раздвигает приёмы по равномерной сетке или гарантирует интервал 3-5 ч между белковыми
  приёмами.** Отсюда «завтрак → сразу обед», «предтрен → сразу следующий приём», если времена
  пользователя сдвинуты.
- Существует только *информационная* проверка MPS-разрыва (`>5ч` — заметка, `:2024`), но она не
  двигает приёмы.

### 2.4 Тренировочные приёмы занимают слоты обычных приёмов — подтверждено
`prew / postw / intra` добавляются в тот же массив `meals` (`:1451/1462/1470`) и **учитываются в
`mealsCount`** (роль-тримминг `:1286` отбрасывает `snack2/intra/snack/preSleep/prew`, если приёмов
больше лимита). То есть на тренировочный день пользователь фактически теряет перекус/пред-сон
из-за пред/пост-трена. **Пери-тренировочные и пред-сон приёмы должны считаться ОТДЕЛЬНО от
базового числа приёмов**, а не съедать слоты. Жалобы №4.

### 2.5 Количество приёмов ограничено 8 — подтверждено
- UI пилюли `[3,4,5,6,7,8]` — `IndividualPlanSettings.tsx:1330`;
- `PopupNumber min=3 max=8` — `:232`;
- авто-подбор `Math.min(8, …)` — `:343`;
- инициализация `v>=2 && v<=8` — `IndividualPlanContext.tsx:737`.
- Движок имеет максимум **9 ролей** (`breakfast/lunch/dinner/prew/postw/intra/snack/snack2/preSleep`);
  `snack2` включается при `mealsCount>=6`. Для 10 приёмов нужно добавить роль `snack3` и поднять
  гейты.

### 2.6 Перекусы / кнопка «порошки и хлопья» — подтверждено
В рендере (`MealListRender.tsx`) **нет** разбивки перекуса на «порошки/хлопья/протеин» — всё
смешано в единый список чипов приёма. Кнопка-категория «💊 Добавки с фиксированной дозой»
существует только в попапе замены/добавления (`MealQuickControls.tsx:188-191`). Отдельного
быстрого «собери перекус из порошка + хлопьев + сухофруктов» нет. Жалоба №8.

### 2.7 Углеводная «добивка» сухофруктами/бананом — отсутствует
В `buildWholeMeal` углеводы берутся из `pool.carbSlow`/`carbFast` (крупы/злаки). Если крупяной
порции не хватает под цель (уперлись в кап), **нет логики добить оставшиеся углеводы фруктом
(банан) или сухофруктами** как вторичным источником. Отсюда «нечем добить адекватным числом
сухофруктов». Жалоба №9.

### 2.8 Молоко / кокосовое масло — выбора нет
Дневник исключает молочные только через `dietPrefs no_dairy` / аллерген `молочные`/`лактоза` /
`lactose_intolerance`. **Нет настройки «добавить молоко/кокосовое масло/жиры в рацион»** как
осознанного выбора пользователя (например «добавлять молоко к завтраку, если не без молочки»).
Жалоба №11.

### 2.9 Таймлайн дня — сжатый, без переноса
Вертикальный «⏳ Таймлайн дня» (`IndividualPlanResults.tsx:856-903`) и основной список
`MealListRender` отображают приёмы **фиксированным шагом без переноса строки**; единственная
часовая разметка — горизонтальный график (`MealListRender:297-354`). Карточка приёма сжимается,
длинные названия/продукты не переносятся. Жалоба №6.

## 5. Ожидаемые тесты для раунда реализации

- **Движок (meal-plan-engine):**
  - завтрак ≠ ужин по составу (завтрак не содержит «обеденного» белка/крупы без ягод/банана);
  - приём не превышает 280 г крупы и при упоре в кап добивается фруктом/сухофруктами (E5);
  - при перегрузке приёма появляется заметка «увеличьте число приёмов» (E4);
  - интервалы между белковыми приёмами в диапазоне 2.5-5.5 ч после перепланировки (E2);
  - пери-приёмы/пред-сон не вытесняют базовые при `mealsCount` (E3);
  - `mealsCount=10` строит до 10 ролей (E6).
- **UI:** кнопка перекуса «порошки/хлопья» работает; настройка молоко/кокосовое масло; таймлайн с
  переносом; предупреждение перегрузки с предложением увеличить приёмы.
