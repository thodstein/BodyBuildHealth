## 1. Аудит — что есть сейчас и где болит

### 1.1 Шелл хаба: 3 изолированных калькулятора без конвейера
- `VolumeHub` — только переключатель `volume|tonnage|plates` + sticky-навигация. Общего стейта нет:
  строки объёма нельзя одним кликом прогнать через тоннаж и разложить на блины.
- Нет deep-link `?mode=plates&weight=` (StrengthAnalysisHub G5/G22 просит линк «раскладка» — вести некуда).
- Нет снапшота/истории (`he_volume_history` отсутствует), нет экспорта (в отличие от ББ/ТА/СМ-хабов),
  нет импорта из дневника (`SessionPlayer`/`he_workout_log_v1` рядом, хаб их не читает).
- `initialMode` маппится в `TrainingScreen` вручную (`tonnage|calc_plates`) — хрупко, без URL-канона.

### 1.2 Объём: два канона объёма конфликтуют + выдуманные формулы
- Канон `VOLUME_LANDMARKS_DB` (15 мышц × 4 уровня, delt_front MEV=0, composite legs/arms) — в коридорах RP 2026,
  претензий к числам нет. Но `VolumeOptimizerTab quality` считает по СВОЕМУ канону:
  `mrvBase 15/20/24/28 + labMult` на 5 грубых групп `chest/back/legs/shoulders/arms`
  (`VolumeOptimizerTab.tsx:107-109`) — третий канон в проекте (первые два — см. QUALITY-HUB-PRO-PLAN §1.2).
  Один и тот же chest 18 сетов — «approaching_mrv» в движке и «норма» в карточке качества.
- Нет MV (maintenance volume, RP: 0–6) — поддерживающий объём клеймится «ниже MEV».
  Нет session-MAV (RP: 5–12 прямых сетов/мышцу/сессию) — 20 сетов груди в 1 день проходят недельный гейт.
- Нет direct/effective-различения: жим лёжа даёт грудь+переднюю дельту+трицепс только как «грудь»;
  S3 (`analyzeManualVolume`, indirect 0.45/0.35/0.4) уже умеет — паритет не доведён.
- Только 5 групп в `analyzeFullVolume` (`chest/back/legs/shoulders/arms`), дельтовидные пучки/ягодицы/икры/пресс
  в per-muscle анализе отсутствуют, хотя канон их знает.
- Выдуманные формулы без источников: `recoveryHours = sets*4 + heavy*8 + compound*3` (`:289`),
  `CNS maxRec = 80`, веса `5/2/2/0.5` (`:352-360`), `maxRecoverable = ΣMRV × levelMult × 0.7` (`:392`),
  `optimalFreq = sets<=MEV ? 2 : <=MAV ? 2 : 1.5` (`:290`) — константа вместо Schoenfeld/Grgic.
- `generateProgression`: `setsScale = targetSets / ΣsetsByMuscle × r.sets` (`:148`) — математически бессмысленно
  (делит целевой объём мышцы на суммарный объём всех мышц); вес `×(0.95+wi*0.02)` — линейка без источника.
- `improveVolume`: `-1 сет всем over-группам + compound первой попавшейся` (`:166-186`) — наивный фикс,
  без session-MAV/частоты/SFR-ранжира.

### 1.3 SFR: hand-tuned таблица 36 паттернов без калибровки
- `SFR_DB` (stimulus/local/systemic 0–100 + tier S/A/B/C) — все числа ручные, источников нет;
  `sfrRatio = stimulus/(local+systemic)` — не Israetel (у него SFR качественный, не арифметика).
- Покрытие 36 паттернов; кабельные/машинные/односторонние варианты — через fuzzy-fallback на generic
  (`squat/bench_bar/row_bar/ohp/barbell_curl`), что занижает SFR именно машин (где он выше всего).
- Нет length-bias (Maeo/Kassiano/Wolf/Strey — длина бьёт короткую), нет stability/bracing-скора,
  нет SRA-окна, нет связки RIR→SFR (Refalo: 1–2 RIR ≈ отказ; тяжёлые 0 RIR — штраф SFR).
- Свапы (`findBetterExerciseSwaps`) ранжируют только по `sfrRatio+0.1` без фильтра оборудования/травм/
  уровня (новичку предложит гакк/нордик), без дедупа по паттерну (3 жимовых варианта подряд).

### 1.4 Тоннаж: КПШ ≠ Прилепин, зоны crude, мост в план — мусор
- `memo.totalKpSh = Σ tonnage × intensity` — это НЕ КПШ Прилепина (у него таблица оптимум/диапазон по зонам
  %1RM + INOL = reps/(100-intensity)). Хаб упоминает «Prilepin 1974» в шапке VolumeHub, но таблицы нет.
- Зоны `<60/60-80/>80%` — грубые; у Прилепина 4 зоны (`<70/70-80/80-90/90+`), у INOL — непрерывная шкала;
  становая без скидки −20…−30% (точка PoinT GO), аксессуары судятся как база.
- Один `oneRMGlobal` на все упражнения (жим 80 и тяга 60 от одного 1RM=100) — %1RM врёт везде, кроме одного лифта;
  per-row `oneRM` есть, но дефолт «0 = общий» толкает к общему.
- Нет RPE-учёта (hard sets RPE≥7 — стандарт RepRaptor/RPE Training), нет веса тела для подтягиваний/брусьев,
  нет pattern-множителей (1.00/0.85/0.65/0.75 — GymCreek).
- Кнопка «🛠 В план»: `sets[m] = tonnage/(oneRMGlobal*8)` (`TonnageCalcTab.tsx:170`) — бессмысленная конверсия
  тоннажа в сеты; такой мост нельзя оставлять.
- Сохранение — один слот `he_saved_tonnage_calc` без истории; экспорта/печати нет.

### 1.5 Блины: лучший таб хаба, не хватает 6 фич топ-приложений
- Есть: 8 грифов, метрика/империя, жадный алгоритм, порядок навешивания, SVG-визуализация, разминка,
  1RM-% пресеты, кастомные блины строкой, пресеты `he_plate_presets` (кап 20), экспорт в clipboard, Apply в план/сессию.
- Нет (есть у PerSide/PlatePal/Iron Calc/StrengthLevel): учёта ЗАМКОВ (2.5 кг пара меняет фактический вес);
  дробных блинов 0.5/1.0 в дефолтном наборе; инвентаря с КОЛИЧЕСТВОМ (только номиналы — «блинов 25 всего 2 шт»
  не выражается); reverse-калькулятора («что на штанге?» — тап по блинам → вес); ближайшего собираемого веса
  при несобираемом целевом; % -таблицы от 1RM с привязкой к наличию блинов (PlatePal); `prompt()` для имени
  пресета (нативный UI, блокирует поток — заменить модалкой).
- `unit` переключатель сбрасывает `targetWeight` в 100 (`:178`) — теряет ввод; `barWeight` правится вручную
  без привязки к выбранному грифу (рассинхрон `barId` vs `barWeight`).

### 1.6 UX: god-компонент + нет действий

## 2. Интернет-синтез 2024–2026 (что берём в план)

1. **MEV/MAV/MRV + MV — калибровка, не догма.** RP/Israetel + Arvo 2026 + TrainerStudio + MesoStrength + RepRaptor:
   MV 0–6/4–8 (поддержание; передняя дельта/трапы/пресс MV=0 допустим); MEV ~6–10 (грудь 8–10, спина 8–10,
   квадры 6–8, хамсы 4–6, бок.дельта 6–8, бицепс 6–8, трицепс 4–6, икры 6–8); MAV ~12–22 (грудь 12–20,
   спина 14–22, бок.дельта 12–22, квадры 12–18, бицепс 14–20); MRV ~20–26; enhanced +~15%.
   Наши `VOLUME_LANDMARKS_DB` в коридорах — **числа не переписываем**, добавляем MV + session-кап + effective-объём.
   Schoenfeld 2017 dose-response (10+ сетов +36% к <5) — MEV-гейт держим строгим.
   Мезоцикл RP: старт MEV → +1–2 сета/нед через MAV → касание MRV → делод на MV (1 нед ×0.4–0.6).
2. **Частота: 2× минимум при равном объёме, дальше — делёж.** Schoenfeld 2016 (2×>1×, p=0.002);
   Grgic/Schoenfeld 2018–2019, Hamarsland 2022 (2×≈3–4× при equated volume). Правило хаба:
   объём ≤MAV → 1× допустим (info); >MAV → требовать ≥2× (разбить, не резать); 2× vs 3× — не штрафовать.
3. **Hard/effective sets вместо сырого тоннажа.** RepRaptor/RPE Training 2026: primary-метрика — hard-сеты
   (RPE≥7 / RIR≤3), тоннаж — вторичная (сравнение идентичных блоков, делоды, периодизация).
   Effective sets = hard × RPE-вес × overlap-коэффициенты компаундов (0.5–1.0 вторичным).
   Разводка «жим 12 сетов = грудь 12 + перед.дельта ~8 + трицепс ~6» — чинит direct/effective (§1.2).
4. **SFR — качественный фильтр, не арифметика.** Israetel 2024–2025 (BarBend/RP guides) + Outlift + Hardgainer:
   высокий SFR = машины/поддержка/направляющие (гакк/пресс ногами/грудь-поддержка/кабели) + длина-растяжение
   (RDL/инклайн/overhead/глубокий присед) + низкий bracing-cost; низкий SFR = становая/низкий присед/тяга в наклоне
   для гипертрофии (оставить для силы). RIR 1–3 — золотая середина SFR; гринд в отказ — SFR падает.
   Вывод: SFR-таблицу расширяем (60+ паттернов с length/stability-флагами), свапы фильтруем по оборудованию.
5. **Прилепин + INOL — канон тоннажа.** Prilepin 1974 (4 зоны: <70→24 / 70–80→18 / 80–90→15 / 90+→7, диапазоны
   18–30/12–24/10–20/4–10) + Hristov INOL (reps/(100−intensity), оптимум 0.8/упр, 0.2/сет; день 2.4, неделя 7.2) +
   StratFit minuend-уточнение + PoinT GO: становая −20…−30%, скорость-валидация зон.
   Вывод: в тоннаж-таб добавляем таблицу Прилепина + INOL per-set/exercise/day/week + становая-скидка.
6. **Блины: стандарт топ-приложений.** PerSide (мульти-инвентарь локаций), PlatePal (reverse + % + nearest-loadable),
   Iron Calc (1RM 3 формулы + RPE + warmup-ramp), StrengthLevel (история + кг/фн-тоггл).
   Вывод: замки + дробные + инвентарь-количество + reverse + nearest + % -таблица + история (без локаций — нет кейса).
