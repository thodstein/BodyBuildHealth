# План доработки планировщика питания — «качественный рацион для бодибилдинга» (Aug 30 2026)

Полный аудит текущего состояния (4 research-прохода: ядро / рецепты / цели+UI, + верификация) и план работ.
База: meal-plan-engine.ts 4536 строк (`@ts-nocheck`), IndividualPlanContext.tsx 3381 строк, RECIPE_DB 939 рецептов (35 шард, p12–p25 пустые), FOOD_DB 1347 id, 40 тест-файлов.

## 0. Диагностика (что мешает качественному рациону сегодня)

### Критические находки (проверено в коде)
1. **`@ts-nocheck` на всём ядре** — meal-plan-engine.ts:1: 4.5k строк генератора вне type-check.
2. **Разрыв «TDEE-наука → фактические цели»**: `calcTargets` → `computePlannerTargets` (planner-targets.ts:199 — bulk surplus, ААС +0.3 г/кг, weight-adapt ±20%, metabolic adapt, женский дефицит ≤22%) считается, но в генерацию доезжает лишь частично. Фактические цели собираются в Context:806–842: `effectiveP = weight × пресет белка`, `effectiveF = max(0.8 г/кг)`, `effectiveC = потолок углей`, kcal = Atwater от них. ААС/phase/surplus/weight-adapt влияют только через углеводную цель.
3. **Мутация кэша пулов**: meal-plan-engine.ts:2415 `pool.carbSlow = [..._strictLowGi]` мутирует объект из `_poolCache` (ключ кэша не включает carbGiPref) → strict-low-GI протекает во все последующие дни 7-дневной генерации.
4. **Квоты дня не действуют на рецепты**: assembleRecipeDay (planner-recipe-mode.ts:736–965) вызывает только порошковый гейт; семейства гарниров/орехи/масла/яйца/фрукты (food-availability.ts:163–179) — мимо. Рецептурный день может дать рис ×3 + яйца 180 г + масло в каждом приёме.
5. **38 пери-рецептов (p32/p35: preworkout/postworkout/presleep) недостижимы**: слот-разметка ставит рецепты только в Завтрак/Обед/Ужин/один снек (planner-recipe-mode.ts:755–771), при этом V2-движок строит пери-приёмы продуктами в 100% дней.
6. **autoCorrectPlan опасен при переборе**: Context:3060–3119 — `remaining = max(0, …)` → при переборе все приёмы (кроме завтрака/предтрена) режутся ×0.3; только dayPlan-only; ломает консистентность kcal=4Б+9Ж+4У (3089–3101).
7. **Разнообразие сбрасывается между неделями месяца**: `_usedRecipeNames`/recentFoodIds создаются внутри generatePlan (Context:2518, 2497) → месяц = 4 независимые недели; hardWindow (жёсткое окно 2 дня) включён только в strict-режиме и сам отключается при `freshPool < 3` (meal-plan-engine.ts:953–956).
8. **Три разных лимита орехов**: квота 60 г (food-availability.ts:172) vs катчеллы 70 г (meal-plan-engine.ts:3811, 4181) vs тест ≤75. Аналогично 5 несовпадающих наборов полов порций белка (80/90/110, 60/70/80…).
9. **Мёртвый код**: prewProteinFor/postwProteinFor (meal-plan-engine.ts:202–203, дублируются живым periProteinBudget:4405 с другими коэффициентами 0.32/0.5 vs 0.25/0.40); meal-planning-system.engine.ts (293 строки, 0 импортов); nutrition-meal-plan.engine.ts (327 строк, фарма-правила конфликтуют с движком: 60 г carbs vs доза×10 г); meal-tier-generator.engine.ts (жив только CustomFood); 14 пустых шард p12–p25; coconutOilBoost (мёртвая настройка); specificity (UI удалён, движок жив).
10. **Пересчёт totals скопирован ~30 раз** (reduce по meals) в meal-plan-engine.ts — источник прошлых багов stale fiber/leucine, не вылечен.

### Контентные пробелы (939 рецептов)
- **Завтраки под массу**: 0 рецептов 600–749 ккал, 164 из 179 ≤550 ккал (цель завтрака на 4000 ккал = 875–1000).
- **Снеки 300–500 ккал**: 43/159; 96 снеков ≤300 ккал — пятый приём на массе недопокрыт.
- **Low-carb**: 8 рецептов + «низкий уголь» 22 — на 7 дней × приёмы не хватает; без глютена 5, lactose-free/nut-free 0.
- **Веган**: 24 рецепта (2.5%), из них **7 с противоречащими тегами** («Кари панир» с chicken_breast); аллергены у 23 легаси-рецептов без ids не гейтятся вовсе (recipe-engine.ts:305–313).
- **Перекос белка**: куриная грудка в 32% рецептов, яйца 24%, сыр 23%; свинина/баранина/субпродукты ≈ отсутствуют; «высокий белок»-тег у 78% БД (не информативен); 60 шумных тегов с count ≤2.
- **Используемые поля-пустышки**: baseWeightKg = 0 везде (D5 вес-якорь фактически мёртв), pairsWith пуст (flavorCompatibilityScore не влияет), batchFriendly у 488 = автогенерация без смысла.
- **Enrichment перезаписывает авторские id** («Протеиновые панкейки»), 24 ключа-сироты.
- **Ккал-гейт приёмки рецепта ±25%** пропускает половинный недобор → сайд-добивка «рис/гречка/оливковое масло» из фиксированных TOPUP-пулов возвращает однообразие.

### Диетология / UX
- **V2-скоринг (947 строк: DIAAS, фазы, фарм, лабы) не участвует в генерации** — только пост-отчёты.
- **Два несогласованных health-score** (planner-reports.ts:81–88 tier-скоринг vs product-usefulness-v2), **две EA-функции** (planner-ea.engine vs planner-female-cycle.computeEnergyAvailability с разными порогами).
- **Компенсация дневника — только день 0** (Context:2745); дни 1–6 недели строятся без учёта факта.
- **Женский цикл — ручной ввод фазы** (Settings:506), без календарного расчёта.
- Нет целей на приём от пользователя; нет «день ног = высокие угли» как явной настройки; EA/micro-заметки без кнопок-действий.
- **Масштабирование**: квоты орехов/масел/фруктов/яиц не масштабируются от веса → 120+ кг атлет на 5000+ ккал упирается в потолок жиров-добора; при 6000 ккал основные приёмы ~1200 ккал упираются в carbPortionCap и «Перегрузка приёма» (второй гарнир удалён D-28).

## 1. План работ

Порядок: **A → B → C → D → E → F → G/H** (A/B — фундамент и гигиена, дальше качество рациона). Каждый эпик заканчивается тестами и зелёной областью.

### Эпик A — Единая целевая арифметика (P0, «цели из науки, а не пресетов»)
**Файлы**: IndividualPlanContext.tsx, planner-targets.ts, NEW `planner-day-targets.ts`.

- **A1.** NEW `planner-day-targets.ts`: чистая функция `buildDayTargets({profile, settings, phase, peds, injections, weightAdapt, metabolicAdapt, cycling, femalePhase, prepPlan, trainDay, dayOffset})` → `{kcal, p, f, c, breakdown[]}`. Внутри — вся логика, которая сегодня размазана между `calcTargets` (Context:712–730), `effectiveP/F/C` (Context:806–842) и `buildOneDay`-модами (2563–2638): bulk surplus → ккал (не через пресет белка), ААС +0.3 г/кг, GLP/инсулин-правила, weight-adapt ±20%, metabolic adapt, женский ≤22% дефицит, female-cycle ×ккал, cycling (cheat/refeed/2:1/5:2/БУЧ), prep-цели. Context — тонкий вызов.
- **A2.** Пресет белка 1.6–2.6 г/кг остаётся пользовательским оверрайдом поверх расчёта (не основой). Surplus-слайдер 5–25% конвертируется в ккал-профицит поверх TDEE, белок фиксирован г/кг, остаток в углеводы.
- **A3.** `breakdown[]` → строки-заметки дня («TDEE 3100 · профицит +15% · ААС +0.3 г/кг → цель 3900») в Settings/Results.
- **A4. Тесты**: NEW `planner-day-targets.test.ts` — инвариант «фактическая цель дня ≈ buildDayTargets» для auto/manual/profile × mass/cut × ААС/без × female; weight-adapt меняет цели (сейчас не доезжает — станет тестом); surplus 15% ≠ surplus 5% при равном белке; детерминизм.

### Эпик B — Ремонт ядра meal-plan-engine (P0, гигиена и баги)
- **B1.** Снять `@ts-nocheck` (поэтапно: типизировать MealPlanInput/промежуточные структуры → включить check → чинить). Блокер для всех дальнейших правок ядра.
- **B2.** Фикс мутации кэша: meal-plan-engine.ts:2415 — не присваивать в кэшированный pool; carbGiPref добавить в ключ `_poolCache` (:2154–2163). Тест: 2 дня подряд strict-low-GI — день 2 получает strict-пул из кэша без протечки в другие пресеты.
- **B3.** Единый реестр лимитов: орехи 60/70/75 → один источник (food-availability QUOTA_LIMITS), катчеллы читают из него; 5 наборов полов порций → `PORTION_FLOORS` один объект с ролью/контекстом; B3-тест — инвариант конца пайплайна «квоты соблюдены после ВСЕХ коррекций» (сейчас тест шире обоих лимитов).
- **B4.** `recalcTotals(plan)` хелпер — замена 30+ копий reduce; юнит-тест на fiber/leucine/leucine_mg после каждого прохода (регресс-защита класса stale-totals).
- **B5.** Удалить мёртвое: prewProteinFor/postwProteinFor (:202–203), meal-planning-system.engine.ts, nutrition-meal-plan.engine.ts (или вынести PHARMA_NUTRITION_RULES в движок, выбрав одну семантику инсулин-углей), meal-tier-generator (кроме CustomFood-экспорта), пустые шарды p12–p25 (перенумерация не нужна, просто удалить импорты и файлы).
- **B6.** autoCorrectPlan: guard перебора (перебор — резка через `correctDayToTargets`, не ratio×0.3); после правки — пересчёт kcal по Atwater-формуле item'ов; поддержка три/7-дней (правка активного дня через weekEditDay-синк, как duplicateMeal).
- **B7.** id-безопасность: NEW тест «все захардкоженные списки id (PROTEIN_ROTATION, BREAKFAST_*, fastProtein/slowProtein, eaa/dextrin/isotonic, TOPUP_*, side-пулы, VEG_COLOR_GROUPS, Mg/мелатонин-пулы) существуют в FOOD_DB» — чинит класс тихих пустых пулов.
- **B8.** Квоты ×weightScale (орехи/масла/фрукты/яйца): ws = weight/80, кламп ×1.6 — снимает потолок 120+ кг атлетов. Тест: 130 кг / 5000 ккал — жиры-добор не блокируется орехово-масляным лимитом.
- **B9.** postw `target.c` — фактический carbG вместо хардкода 60 (:1870). Мелочь, правится в B-пакете.

### Эпик C — Рецептурный режим до продакшн-уровня (P1)

- **C2. Пери-слоты по рецептам**: isMainMealLabel/slot-разметка (planner-recipe-mode.ts:755–771) — preworkout/postworkout/presleep-рецепты ставятся в соответствующие приёмы дня (prew только при trainDay, presleep ≤400 ккал/≤25 г углей); фолбэк на продукты сохранён. Тест: день с тренировкой содержит p32/p35-рецепт в пери-слоте при включённом режиме.
- **C3. Аллергены/вег для всех рецептов**: гейт по decomposedFacts/ingredientIds для легаси (23 рецепта) + чистка 7 противоречивых вег-тегов; тесты «vegetarian → ноль мяса», «no_dairy → ноль молочки» на всём пул-пути.
- **C4. Контент-пакеты** (шарды p36–p38, грамовки по формуле kcal=4Б+9Ж+4У сразу):

  - p37: 25 снеков 300–500 ккал (творожные, бутербродные, шейк-боулы) + 10 суша-обедов;
  - p38: 30 low-carb (сушка) + 20 веган с чистыми тегами + аллерген-теги (lactose-free/gluten-free/nut-free) проставить по ингредиентам скриптом (scripts/tag-recipes.mjs), не руками.

## 2. Критерии приёмки (Definition of Done по рациону)

1. **Цели**: фактическая цель дня = buildDayTargets (±0) во всех режимах; breakdown виден в UI; weight-adapt/AAC/surplus реально меняют план (тесты A4).
2. **Точность**: день ≤3% по ккал/Б/Ж/У (существующие property-тесты зелёные), рецепт-день — ядро рецепта ≤±14% (текущий задокументированный допуск) с честным withinTolerance.
3. **Реализм**: все квоты (гарниры/орехи/масла/яйца/фрукты/порошок) соблюдаются в конце пайплайна И в рецептурном дне (единый лимит-реестр, тесты B3/C1).
4. **Разнообразие**: 7-дневные гарантии D3; месяц без межнедельного сброса.
5. **Рецепты**: пери-слоты достижимы (C2), аллергены гейтятся для 100% БД (C3), дыра завтраков 600–950 закрыта (C4).
6. **Диетология**: v2-скоринг влияет на выбор (E1), EA одна функция, health-score один (E3/E4).
7. **Гигиена**: @ts-nocheck снят (B1), мёртвые файлы удалены (B5), totals один хелпер (B4), tsc 0, полный прогон IndividualPlan-области зелёный (~464+ новых/обновлённых тестов).

|---|---|---|---|
| A | 3 (1 new) | ~15 | средний (трогает все пути целей) |
| B | 6 + удаление 5 | ~20 | средний (nocheck-снятие) |
| C | 5 + 3 шарда + скрипт | ~18 | низкий |
| D | 3 | ~10 | низкий |
| E | 4 | ~10 | низкий |
| F | 2 | ~8 | низкий |
| G | 4 | ~8 | низкий |
| H | скрипты + шарды | ~6 | низкий |

Порядок даёт быстрый эффект: A+B убирают «декоративные» цели и баги-протечки (это то, что пользователь чувствует как «план не по КБЖУ/не по мне»), C+D — «скучный однообразный рацион», E+F — «рацион не по-бодибилдерски».
