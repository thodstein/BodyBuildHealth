## 2. Найденные и исправленные баги

### B1. Дублированный `aria-label` кнопки «Применить»
- **Где:** `ArmliftingDiagnosticsHub.tsx`, две кнопки (`lift-apply-top` и `lift-apply-bottom`) имели одинаковый `aria-label="Применить в Арм-конструктор"`.
- **Симптом:** `getByLabelText` в тесте падал (multiple elements), доступность дублировалась.
- **Фикс:** верхняя кнопка получила уникальный `aria-label="Применить замеры в конструктор"`; нижняя сохраняет исходный. Поведение и `data-arm` не изменились.
- **Проверка:** `armlifting-pro4-hub` 5/5, весь набор армлифтинга 96/96.

### B2. `annualStartWeek` не восстанавливался из localStorage
- **Где:** `loadState()` в `ArmliftingDiagnosticsHub.tsx` собирал `LiftState`, но поле `annualStartWeek` не читалось из сохранённого JSON — после перезагрузки сбрасывалось в `'1'`, хотя UI сохранял значение.
- **Симптом:** годовой overlay спец-блока всегда стартовал с недели 1 после перезагрузки; пользовательская настройка терялась.
- **Фикс:** добавлено чтение `annualStartWeek` с валидацией диапазона 1–52 (невалидное → `'1'`).
- **Проверка:** type-check 0, целевые тесты зелёные.

## 4. Оставшиеся пробелы до «профессионального инструмента» (приоритизировано)

### P0 — достоверность измерений
1. **Калибровка дисков и веса**: UI просит «диски калиброваны», но нет поля фактической массы диска/погрешности; professional tool должен хранить поправку и пересчитывать %WR.
2. **Версия снаряда (RT V1/V2/V3)**: условие хранится в диагностике, но не влияет на WR-сравнение. Нужен флаг «V3 verified» и отдельная норма/предупреждение для V1/V2.
3. **Температура/мел/диаметр**: собираются, но не нормализуются в %WR (только training-only). Добавить корректирующий коэффициент с явной пометкой «скорректировано».

### P1 — нормативная база
4. **Весовые/возрастные нормы**: сейчас только % от абсолютного WR. Профессиональный инструмент нуждается в перцентилях по полу/весу/возрасту (хотя бы 4 уровня: новичок/средний/продвинутый/элита) и источникам.
5. **Pinch**: внутренний ориентир 80/45 кг не является WR; нужен переход на реальные IronMind Block WR (51.40/31.55) с учётом ширины блока, либо явный «не сравнимо».
6. **CoC**: poundage-оценка No.3 = 100% — корректно как сертификация, но нужен отдельный «закрытие уровня» без ложной точности кг.

### P2 — повторяемость и валидность
7. **Test-retest**: есть перетест, но нет ICC/CV и доверительного интервала; добавить расчёт и предупреждение при расхождении >10%.
8. **Стандартизация протокола**: время отдыха, порядок снарядов, разминка, количество попыток — вынести в «протокол замера» и логировать.
9. **Фото/видео доказательство**: Kinovea-парсер есть, но нет привязки к конкретному замеру; добавить ссылку на видео в запись журнала.

### P3 — аналитика и UX
10. **Дашборд трендов**: есть `liftTrendFromLog`, но нет графика/экспорта перцентиля; добавить визуализацию и PDF.
11. **Сравнение с командой/нормой**: нет сравнения с группой; добавить анонимизированные бенчмарки.
12. **Мобильная эргономика**: поля 48px есть, но длинные формы; добавить пошаговый мастер замера.

### P4 — интеграция и безопасность данных
13. **Синхронизация**: localStorage-only; для профессионального инструмента нужен экспорт/импорт полного профиля и бэкап.
14. **Версионирование данных**: ключи `he_armlifting_diag_v1` и т.д. не имеют миграций; добавить схему версий.
15. **Конфиденциальность**: данные здоровья/боли; добавить явное согласие и локальное шифрование при экспорте.

- Любой замер имеет: снаряд/версия, протокол, дата, условия, результат, %WR/перцентиль, confidence.
- Повторный замер показывает Δ и CI; при расхождении >10% — предупреждение.
- Экспорт содержит полный аудит-след (кто/когда/чем/как).
- 0 ошибок type-check и 100% целевых тестов на каждом этапе.
- `verify:apk-design` зелёный для APK-UI.

## 7. Риски

- Нормативные данные по армлифтингу фрагментарны; перцентили потребуют сбора собственной базы или честного «нет нормы».

- Не трогать чужой WIP (SessionPlayer/ExecutionZone/LiftMasterCard и др.) — изменения только в армлифтинг-хабе.

## 11. Исследование оставшихся пробелов (2026-10-17)

### Нормы силы хвата (общие, не снаряды)
- Источники: PMC systematic review 2024 (2.4M adults, 69 стран), NHANES, Canadian Health Measures Survey, немецкие нормы.
- Вывод: перцентили по возрасту/полу/росту существуют для Jamar-динамометра, но не для RT/Axle/Saxon. Для армлифтинга %WR остаётся основой; общие нормы можно показывать как справку («общая сила хвата») без подмены %WR.
- Рекомендация: добавить опциональное поле «общая сила хвата (кг)» и показывать перцентиль по возрасту/полу из открытых таблиц (без привязки к снарядам).

### ICC/test-retest
- ICC требует ≥3 повторных замеров; у нас 2. Реализован CV (>10% предупреждение). Полноценный ICC — только при накоплении ≥3 замеров в журнале.

### Графики/мастер (волна 4)
- Без графической библиотеки (chart.js/recharts) реализовать только текстовые тренды (уже есть `liftTrendFromLog`, `completenessTrend`). Полноценные графики — отдельная зависимость.

### Миграции/согласие (волна 5)
- Добавить `schemaVersion` в payload (сделано) и миграцию при загрузке. Согласие на хранение данных здоровья — отдельный экран/флаг.
