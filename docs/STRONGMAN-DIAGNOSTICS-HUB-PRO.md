## 2. Интернет-синтез 2024–2026 (проверено поиском Sep 11 2026)

- **Hindle et al. 2021 (Frontiers, n=19, 20м @85%):** йок = сгибание таза + нейтраль колена на heel-strike, короткая длина шага 1.14м vs фермер 1.54м, темп 1.62 Гц vs 1.89 Гц, stance 0.42с vs 0.32с; интервал 0–5м — короче шаг + выше темп + меньше ROM (разгон), дальше — крейсерская. Порог: свыше ~%1RM темп не компенсирует падение длины → падает скорость. Женщины — короче вторая тяга камня, больше сгибание таза (Hindle stone 2021, n=20). **Вывод:** наши отрезки 0–5/5–15/15–20м верны, но нет модели `скорость = длина × темп − k×нагрузка/BW` и разбора «разгон vs крейсер».
- **Renals et al. 2018 (JSCR, log push press):** малый лог +6% мощность, +2% скорость, +5% импульс, +3% сила vs большой; штанга выше лога по всем фазам. **Вывод:** наш `logDiameterClass ≤26/27–30/≥31 + ×1.03/1.00/0.97` корректен, но нет привязки диаметра к соревновательному логу («тренируйся на соревновательном размере» — FitnessVolt/BarBend).
- **Hindle stone 2021 (PMC 8418215):** 5 фаз (recovery/grip/1st pull/lap/2nd pull), max-сгибание таза в начале 1-й тяги, max-сгибание колена во 2-й; zero-lap («one-motion») у топов; grind vs pop техники 2-й тяги. **Вывод:** наши 3 фазы (1-я/колени/2-я) — упрощение; нужны 5 фаз + детект zero-lap + pop/grind.
- **Winwood 2014 (n=213/454):** камень — самый травмоопасный (бицепс + поясница), 82% травм, 91% на ≥90% 1RM; тейпер шаговый −52% объём, прекращение за 3.9д. **Вывод:** наш гейт ≥70/бицепс-риск верен, но нет запрета «камень ≥90% вне пика» и явного cessation-счётчика по дням до старта.
- **IJSPT 2022 (distal biceps repair case):** разгибание локтя под нагрузкой + супинация = механизм; прогрессия только shared-decision + BFR. **Вывод:** нужен cue «руки-канаты, локти прямые, хват вперёд центра» на каждый сет камня + mixed→hook/лямки чек (у нас только варнинг).
- **McGill 2009 (спина):** йок — макс. нагрузка на позвоночник из всех ивентов (вес + коконтракция + абдукция бедра через QL); камень — невозможен нейтральный позвоночник. **Вывод:** наш `axialQuant` текст, но бюджет единый — нужен раздельный `compression-бюджет` йок vs фермер vs камень.
- **Grip-нормы 2024–2026:** Jamar M38/F24кг, key-pinch M8.5/F6кг; фермер — хват отказывает раньше ног (FitnessVolt 2000+ стартов); нормы фермера по весовым — Beginner 50–90/рука → Elite 180–280/рука. **Вывод:** наши hold-пороги 30/20/30с без весовых классов — добавить таблицу весовых.
- **Suchomel 2025 (VBT):** barbell vs system velocity g≥1.49 — только peak velocity информативен. **Вывод:** наши пороги carry 15%/log 10% верны, но LVP-профиль один на всех — нужна индивидуальная рампа (уже есть калибровка, но не связана с VBT-гейтом).

## 3. PRO-план (эпики P1–P7, без ломки строк/тестов)

- **P1 yMax-развязка (баг B1+B7):** новое поле `yMaxCm` в стейте, CSV-парс пишет `sway + yMax + vmax`, ручной HubNum читает `yMaxCm`. Тест: ввод yMax не трогает stoneKg.
- **P2 низ-панель (B2):** sticky-низ с `bottom:0 + safe-area + запас под таббар`, единый компонент, дубль CTA в ленте табов — ghost.
- **P3 камень-5-фаз:** `pull1/lap/pull2` → `grip/pull1/lap/pull2/recovery` + zero-lap детект + pop/grind + гейт ≥90% вне пика + cessation-дни до старта.
- **P4 йок-модель:** `скорость = длина × темп − k×нагрузка/BW` (k=0.015 йок/0.010 фермер, Legg/Hindle), разгон 0–5 vs крейсер, порог «темп не компенсирует».
- **P5 осевой бюджет:** раздельные лимиты йок/фермер/камень по McGill (компрессия 3–4×BW), QL-протокол при превышении.
- **P6 весовые классы хвата:** hold-нормы × таблица весовых (FitnessVolt), pinch 2/3/4″ + CoC-уровни уже есть — связать с калибровкой.
- **P7 мост в живость:** ACWR из бейджа в скоринг/спец-блок, `factSetsPerWeek` из дневника в причины, пол-подписка через `profile-updated`, live-углы следующим шагом (MediaPipe tasks-vision, честно после CSV).
