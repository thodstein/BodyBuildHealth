# REALISM-REBASELINE-PLAN — 5 фиксов реализма выдачи без поломки гарантий

Источник: реализм-аудит `docs/NUTRITION-PLANNER-TUNING-PLAN.md` §7.7 (Sep 16 2026) + AGENTS-запись
«реализм-аудит выдачи». Работать ТОЛЬКО по этому плану, по одному пункту = один коммит pathspec.

## 0. Контекст и доказательства (из аудита)

Дампы 4 профилей (M85 масса 3200, M100 сушка 2400, F60 поддержание 1800, M90 max-кардио), неделя
7 дней, проба 16 дней. Уже исправлено и закоммичено (НЕ трогать): витрина `mpsSummary`
пересобирается после всех проходов (`2f60f34b5`).

**Известный эффект правок пулов**: первая попытка (только id-гейты + фруктовый кап) уронила
12 калиброванных тестов — список и числа в §4. Это ожидаемо: экзотические id сидят в tuned-пулах
и участвуют в сходимости. Поэтому порядок: **фикс → прогон → понимание, деградация это или
намеренное изменение → только потом re-baseline теста с комментарием**.

## 1. Что правим (по пунктам)

### P1. Дрейф id гейтов экзотики (проба 16 дней: тамаринд 3×, локва 2×, жеруха 2×, фенхель 4×,

    `passion_fruit`, `fruit_dragon_fruit`, `fruit_papaya_fresh`, `papaya`, `fruit_tamarind`,
    `fruit_loquat`, `greens_watercress` (у их канонических двойников гейт уже есть).
  - фенхель (`veg_fennel_bulb`) — решить: сети РФ бывает, оставить обычным ИЛИ specialty;
    сначала проба, потом решение (не менять «на глаз»).
- Найти и убрать `greens_watercress` из курируемых пулов, где он захардкожен (тест
  `planner-id-safety` B7 «экзотика/specialty в курируемом пуле» это покажет) — гейт и пул

- **Компенсация вместо потери сходимости**: если после удаления экзотики дни теряют

  НЕ расширяя капы/квоты. Цель: состав сходится не хуже, чем до правки.

### P2. Фруктовый кап (4 приёма) пробивается поздними доборами (соль 2, 100 кг/max → 5 при лимите 4)
Готовый гард (был написан и откачен — переносится 1-в-1), ставится в `meal-plan-engine.ts`
ПЕРЕД §realism-пересбором `mpsSummary` и ПОСЛЕ всех доборов:
```ts
    // ─── F1-guard: фруктовые приёмы ≤ maxFruitMeals — финальный инвариант ───
    {
      const _fruitCap = QUOTA_LIMITS.maxFruitMeals;
      const _fruitMealsNow = meals.filter(m => (m.items || []).some(it => it.role === 'fruit'));
      if (_fruitMealsNow.length > _fruitCap) {
        const _rankMeal = (m: any): number => {
          const t = String(m.type || '');
          if (t === 'presleep') return 100; // мелатониновая порция — не трогаем
          if (t === 'breakfast') return 90;
          if (['snack','snack2','snack3','snack4','snack5','snack6'].includes(t)) return 10;
          if (t === 'lunch' || t === 'dinner') return 30;
          return 50;
        };
        let _over = _fruitMealsNow.length - _fruitCap;
        for (const m of [..._fruitMealsNow].sort((a, b) => _rankMeal(a) - _rankMeal(b))) {
          if (_over <= 0) break;
          if (_rankMeal(m) >= 100) continue;
          const before = (m.items || []).length;
          m.items = (m.items || []).filter((it: any) => it.role !== 'fruit');
          if ((m.items || []).length !== before) {
            m.totals = mealTotalsOf(m.items); recalcDayTotals(meals, totals); _over--;
            notes.push(`🍎 Фруктовый кап (≤${_fruitCap} приёма): фрукт убран из «${m.label}» (поздний добор)`);
          }
        }
      }
    }
```
Лок: расширить `planner-realism-guarantees` (уже стережёт ≤4 — после гарда стабильно зелёный).

### P3. Мелкие мясные порции в мейнах при низкой цели белка (индейка 60 г на обед 592 ккал;
креветки 40 г) — кандидат-гард:
- В финале `buildDayPlan` (перед §realism): для основных приёмов (breakfast/lunch/dinner,
  kcal ≥ 450) найти `role==='protein'` item из цельного мяса/рыбы/морепродуктов с amount < 80 г
  → поднять до 80 г, равную ккал-дельту срезать с карбовых items того же приёма (не трогая полы
  карб-приёма и капы), инвариант «≥1 белковый пункт в приёме» сохранить.
- Исключения: веган/вегетарианские дни (нет мяса — и не надо), peri-окна, pre-sleep.
- Гейт: только если дневной белок ≤ 2.1 г/кг (при высоких целях мясо и так большое).
- Риск: сдвиг proteinCV/MPS-витрины (она уже пересобирается после — учесть порядок гарда:
  P3 → P2 → §realism-пересбор).

### P4. Клетчатка на HV-днях до 77 г (25 г/1000 ккал при ориентире 14; гард ≤85 не нарушен)
- Финальный HV-трим: если `input.goalCarbsG ≥ 1000` и клетчатка > `max(50, kcal/1000*14)` →
  резать самые клетчаточные ИЗОЛИРОВАННЫЕ источники (овощи/семена/ягоды сверх 100 г) до потолка,
  не трогая гарниры-носители углеводов и полы приёмов.
- Иначе — оставить как честную границу (тогда зафиксировать в доке без кода).

### P5. Сельдерей-наполнитель 244 г
- `COMFORT_PORTION_LIMITS`/`EDIBILITY_CAPS` (в `meal-plan-engine.ts`/`planner-carb-density.ts`):
  кап стеблевых овощей-наполнителей (сельдерей, огурец, руккола, салат) ~150 г на приём,
  чтобы «объём тарелки» не набирался селлером. Реальные овощи (брокколи/кабачок) не трогать.

## 2. Порядок и правила (обязательно)
1. Один пункт = один коммит pathspec своих файлов (сначала P1, затем P2, P3, P4, P5 —
   от простого к сложному; каждый пункт отдельно прогонять область).
2. После КАЖДОГО пункта: `npx vitest run src/ui/screens/NutritionScreen_parts/IndividualPlan/__tests__`
   (ожидаемо сейчас 926/926; любые падения разобрать: «намеренное изменение» vs «деградация»).
3. **Деградация = чинить код компенсацией (пулы/капы), а не тест.** Тест можно обновить только
   если новое поведение объективно лучше (реалистичнее) И это подписано комментарием с числом
   «было → стало». Инварианты (сходимость ≤8%, капы, квоты, формула КБЖУ, порции ≤350 г,
   тарелки ≤750 г, порошок ≤3 приёмов, яйца/орехи/масла-капы) НЕ ослаблять никогда.
4. Не трогать чужие файлы; не пушить; temp-дампы (`zz-*`) удалять до коммита; после скриптов
   перечитывать файл; tsc 12GB: `$env:NODE_OPTIONS='--max-old-space-size=12288'; npx tsc --noEmit`.
5. Финал: полный прогон проекта (`npx vitest run --reporter=dot`), карта падений в AGENTS;
   `verify:apk-design` (если трогали UI/CSS — тут не должны).

## 3. Приёмка
- P1: в дампе 4 профилей×4 соли нет `fruit_salak/fruit_papaya_fresh/fruit_passion/passion_fruit/
  fruit_dragon_fruit/fruit_tamarind/fruit_loquat/greens_watercress`; фенхель — по решению.
- P2: фруктовых приёмов ≤4 во всех прогонах (включая соль 2/100кг max).
- P3: мясные позиции в мейнах ≥80 г при kcal ≥450 и цели ≤2.1 г/кг; proteinCV не вырос.
- P4: клетчатка ≤ max(50, 14 г/1000 ккал) на HV (или зафиксировано решение).
- P5: стеблевые овощи ≤150 г/приём.
- Область IndividualPlan зелёная; `tsc` 0; полный прогон без НОВЫХ чужих падений.
