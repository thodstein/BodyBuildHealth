### 1.1. Четыре движка темпа с расходящимися цифрами (P0, канон)

| Движок | strength | hypertrophy | power |
|---|---|---|---|

| `rep-tempo-engine` (TEMPO_TEMPLATES) | `2-0-1-0` / `2-0-X-0` | `3-0-1-0` / `3-2-1-0` / `4-1-2-0` | — (conditioning `1-0-1-0`) |

Плюс `MANUAL_TEMPOS` в `TempoTab.tsx:46` (rehab/tut_max/speed/iso_stretch — только в UI, в движках их нет).
Три селектора (`recommendTempo` / `selectTempo` / `generateRepTempo`) с разной сигнатурой и разной трактовкой риска.
Фикс — эпик A: канон `TEMPO_CANON` + адаптеры, цифры существующих планов не меняются (только новые назначения через канон).

### 1.2. `parseTempo` не знает `X` (P0, честность TUT)

`rep-tempo.engine.ts:72` — `split('-').map(Number)`: взрывной `2-0-X-0` → `NaN` → `null` → `ExerciseCalcTab.tsx:398`
`splits tutInfo` падает в `null` («нет TUT» при валидном темпе). Второй парсер (`rep-tempo-engine.ts:39`)
`X` знает, но молча превращает в `0` (скорость ≠ пауза 0 — семантика теряется).
Фикс — эпик A: единый `parseTempoCanon` (`X` → `{value:0, explosive:true}`), оба старых — thin-wrapper.

### 1.3. Карточки паттернов врут (P0, UI-баг)

`TempoTab.tsx:272` — все 8 карточек `REP_PATTERNS` показывают **одну и ту же строку**
(`generateRepTempo({goal:'hypertrophy', risk low, medium, main})`, захардкожен). Пользователь видит
8 разных описаний с одинаковым `3-0-1-0`. `goalTempos` (`:93`) считает только compound/isolation,
без difficulty/risk/techniqueIssues — превью «сост/изол» не совпадает с реальным `generateRepTempo`.
Фикс — эпик F (малый, но обязательный): превью на каноне с реальными входами.

### 1.4. Нет TUT-калькулятора сета (P1, главный продуктовый гэп)

Хаб показывает только `TUL` повтора (`calculateRepDuration`). Нет связки
`темп × повторы × сеты = TUT сета/сессии`, нет зон с честной оговоркой (§2: зоны — ориентир объёма,
а не гарантия роста). `ExerciseCalcTab` TUT считает сам (`:396`) — дубль логики без зон.
Фикс — эпики B/C: `tutForSet/tutZone` в каноне + TUT-панель в хабе (ввод повторов/сетов → TUT + зона + предупреждение «>8с/повт — нагрузка упадёт»).

### 1.5. Нет per-exercise назначения (P1)

`bb-tempo-rest.ts:33` `EXERCISE_TEMPO_OVERRIDES` (30+ записей: присед `2-0-1-0`, RDL `3-1-1-0`,
кроссовер `3-2-1-0`, махи `2-1-1-1`) живёт только в ББ-сборке. Хаб про него не знает:
пользователь выбирает один темп «на всё», мост `tempoHandler` (`:300`) затирает **все сеты всех недель**
одной нотацией без учёта характера/упражнения/deload. Фикс — эпики C/F: пресет «по упражнению»
(ввод имени → override из канона) + мост с режимами `all | compound-only | isolation-only | deload-skip`.

### 1.6. Мост без валидации и без отката (P1)

`tempoHandler`: `payload.data.label ?? join('-')` без `isValidTempo`-проверки (битый payload пишет
`undefined-undefined…` в сеты); применяется только к `p.bb` (ПЛ/ручной — тишина без тоста);
отката нет (перезапись необратима). Фикс — эпик E: валидация + честный тост для не-ББ + снапшот
`he_tempo_prev` для «↩ Откатить темп».

### 1.7. Мусор и нейминг (P2)

- `rep-tempo.engine` vs `rep-tempo-engine` — имена-близнецы, импорты путаются (`TempoTab` тянет оба;
  `training.engine` — первый, `TechniqueCalcTab` — второй). Переименование — только через канон-адаптер,
  прямые правки импортов не делать (30+ потребителей).
- `TUL` vs `TUT` в UI (`TempoTab:147,238` — TUL, `ExerciseCalcTab:747` — TUT). Канон: **TUT**.
- `MANUAL_TEMPOS.speed` (`1-0-0-0`) vs канон power (`1-0-1-0`/`2-0-X-0`): `concentric 0` без пометки
  «взрывная» — семантический дубль. Схлопнуть в каноне с `explosive:true`.
- Персиста хаба нет (`customTempo/filterGoal` не сохраняются — в отличие от `he_excalc_saved`,
  `he_tech_fav`). Фикс — эпик F: `he_tempo_hub_v1`.

**Вывод:** хаб честно показывает изолированный темп, но отвечает не на тот вопрос. Нужный вопрос:
**«какой темп каждому упражнению моего плана и сколько TUT это даст — с применением в один клик»**.

## 3. Концепция «канон → TUT → назначение → мост»

```
TEMPO_CANON (таблица цель×тип + per-exercise overrides + X/intent)
        │
        ▼
parseTempoCanon / tutForSet / tutZone (чистые, тестируемые)
        │
        ├── TempoTab: TUT-панель (темп × повторы × сеты) + пресет «по упражнению»
        ├── ExerciseCalcTab / TechniqueCalcTab / ExerciseLab*: чтение канона (дубли удалить)
        └── tempoHandler: режимы all/compound/isolation/deload-skip + валидация + откат
```

**Одна фраза:** один канон цифр, TUT как доза (не прогноз), назначение — до упражнения, мост — с откатом.

## 5. UI (`TempoTab.tsx`, структура сохраняем, +2 блока)

- **TUT-панель** (под схемой): ввод повторов/сетов → `TUT сета Nс · зона · TUT сессии` + честная нота
  «TUT — доза, рост решают объём + близость к отказу (S1/S4); >8с/повт — вес упадёт».

- **Мост**: селект режима (`Все / Только база / Только изоляция / Кроме делоада`) + «↩ Откатить темп»
  (снапшот `he_tempo_prev`); персист `he_tempo_hub_v1` (customTempo/filterGoal/режим).
- Каталог/калькулятор/лаборатория: цифры из канона (тонкая замена вызовов, тексты целы).

## 7. Критерии PRO

- Один канон: все 4 движка дают те же цифры через адаптеры; расхождений strength/hypertrophy/power — 0.
- Каждый дефолт канона внутри 2–8с/повт (S1-инвариант тестом); `>8с` — только rehab/technique с подписью «не +рост».
- TUT считается для любого валидного темпа incl. `X`; зонные формулировки честные («доза», не «прогноз»).
- Мост: битый payload не мутирует; режимы работают; откат восстанавливает побайтово.
- `tsc 0`, `vitest tempo-canon` **25+** зелёных (A 8 + B 6 + D 5 + E 6), потребители (`rest-hooks-native`,
  `planner-bridge-handlers`, `bb-tempo`) без регрессий.
- 0 дублей: новый файл — строго `tempo-canon.engine.ts`; старые движки — wrapper, не параллельный канон.

## 8. Осознанно НЕ делаем

- Своя «оптимальная TUT-зона гипертрофии 40–70с» как гарантия роста (S1/S4 — нет данных; только ориентир дозы).
- «Медленнее = больше»-пресеты (>8с как гипертрофийные) — противоречат S1.
- VBT-скорости/потеря скорости в этом хабе (канон `StrengthAnalysisHub`/VBT-таба; здесь только `X`-intent пометка).
- Видео-анализ темпа по записи сета (уровень WL-хаба Kinovea; здесь — только ручной ввод).
- Персональный темп-план на мезоцикл (в MVP — разовое назначение + мост).

## 9. Риски

- `bb-tempo-rest.tempoFor` читают ББ-сборка/финализатор/валидатор — канон только читает overrides
  как данные, сигнатуру `tempoFor` не менять (иначе поплывут 30+ калиброванных тестов).
