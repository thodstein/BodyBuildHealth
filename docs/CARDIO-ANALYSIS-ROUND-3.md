- UI: мастер (5 шагов) + 14 компонентов (~2800 строк). 9 тест-файлов, **185 тестов**.

## 2. Новые находки (углублённый аудит данных и UX)

| # | Проблема | Критичность |
|---|----------|-------------|
| 1 | **Нет `startDate` у цикла**: все даты (неделя, прогресс, adherence, «Сегодня», следующая сессия) считаются от «сегодня». Цикл, собранный неделю назад, всегда показывает «Неделя 1 из N» и неверный adherence | **P0** |
| 2 | **Нет снапшота параметров сборки**: готовый цикл нельзя доредактировать в мастере (параметры не сохраняются; «Пересобрать» берёт текущие поля мастера, а не те, из которых собран цикл) | **P1** |
| 3 | **Нет safety-валидации ручных правок**: в редакторе сессий можно наставить 7×180 мин HIIT (1260 мин/нед) без предупреждения | **P1** |
| 4 | **Степперы недели всегда начинаются с 1**: нет «📍 перейти к текущей неделе» (редактор/предпросмотр) | **P1** |
| 5 | **Таблица недель без пагинации**: 52 недели рендерятся сразу (тормозит на слабых устройствах) | P2 |
| 6 | **Расход ккал не связан с питанием**: kcal/нед отображается, но нет моста в планировщик питания (kind 'cardio' в bridge уже есть, но не используется) | P2 |
| 7 | **Нет медиа-запросов в кардио-компонентах** (таблицы дней/степпер на узких экранах — только горизонтальный скролл) | P3 |
| 8 | Крайние тесты: 104 недели / вес 300 / все 7 дней ног — покрыты частично | P3 |

## 3. План доработки

### Этап G (P0) — `startDate` цикла
- [ ] Движок: `CardioCycle.startDate?: string` (ISO); при сборке = сегодня; при миграции = createdAt.
      Все date-функции принимают `referenceIso` — UI передаёт `cycle.startDate` (пока сегодня при отсутствии).
- [ ] UI: CardioProgressCard, шапка «Сегодня», CardioSessionTimer, CardioAutoTunePanel,
      кардио-слой «Итог года» — использовать `cycle.startDate` как reference.
- [ ] Тесты: цикл со startDate неделю назад → «Неделя 2 из N», adherence правильный.

### Этап H (P1) — Снапшот параметров сборки
- [ ] Движок: `CardioCycle.config?: CardioCycleInput` (без id/name/source) — сохраняется при сборке
      и пересборке; `configFromCycle(cycle)` — обратная функция.
- [ ] UI: на шаге «Предпросмотр» кнопка «⚙️ Изменить параметры» → загрузка config в мастер
      (шаг 1) + flash; «Пересобрать» использует config, если он есть.
- [ ] Тесты: roundtrip config; «Изменить параметры» восстанавливает поля.

### Этап I (P1) — Safety-валидация правок
- [ ] Движок: `cardioSafetyReport(cycle)` — предупреждения: сессия > 90 мин, неделя > 600 мин,
      HIIT > 3×/нед, зона > 60 мин подряд; встраивание в `cardioQualityReport` (штрафы).
- [ ] UI: предупреждения в CardioWeekEditor при сохранении и в «Качестве цикла».
- [ ] Тесты: перегруз → warn; норма → нет warn.

### Этап J (P1) — «📍 К текущей неделе»
- [ ] CardioWeekEditor и CardioPreviewStep: кнопка «📍» — степпер к неделе по `cycle.startDate`.
- [ ] Тесты: неделя устанавливается на текущую.

### Этап K (P2) — Пагинация таблицы недель
- [ ] CardioPreviewStep: таблица недель — «показать 12 / все» (по умолчанию 12 при > 16 нед).
- [ ] Тесты: при 52 неделях рендерится 12, «все» — 52.

### Этап L (P2-P3) — Ккал→питание + мобильность
- [ ] Карточка «🔥 Расход N ккал/нед» на предпросмотре + кнопка «📋 ккал в буфер»;
      (мост в NutritionScreen — кандидат на интеграцию, отметить в bridge-доке).
- [ ] `@media (max-width: 480px)` в CardioPreviewStep/CardioWeekEditor: ячейки дней — сетка 4+3.
- [ ] Тесты: буфер-кнопка; SSR с медиа не проверяется (визуально).

## 4. Критерии готовности
- [ ] Прогресс/adherence/«Сегодня» корректны для циклов, собранных ранее;
- [ ] Готовый цикл можно доредактировать в мастере без потери параметров;
- [ ] Ручные правки не позволяют построить опасную перегрузку (с предупреждениями);
- [ ] Быстрый переход к текущей неделе;
- [ ] 52-недельный план рендерится плавно (пагинация);
- [ ] Расход ккал доступен для планировщика питания (буфер);
- [ ] tsc 0, cardio-тесты зелёные, `vite build` OK.
