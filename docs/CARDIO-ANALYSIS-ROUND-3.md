## 1. Текущее состояние (свежие факты)

- Движок `cardio.engine.ts`: **89 экспортов**, `cardio-diary.engine.ts`: **16 экспортов**.
- UI: мастер (5 шагов) + 14 компонентов (~2800 строк). 9 тест-файлов, **185 тестов**.
- Все предыдущие планы закрыты: P0-P3 (варианты/неделя по дням/улучшение/протокол),

- tsc 0 по моим файлам, `vite build` OK.

## 2. Новые находки (углублённый аудит данных и UX)

| # | Проблема | Критичность |
|---|----------|-------------|
| 1 | **Нет `startDate` у цикла**: все даты (неделя, прогресс, adherence, «Сегодня», следующая сессия) считаются от «сегодня». Цикл, собранный неделю назад, всегда показывает «Неделя 1 из N» и неверный adherence | **P0** |
| 2 | **Нет снапшота параметров сборки**: готовый цикл нельзя доредактировать в мастере (параметры не сохраняются; «Пересобрать» берёт текущие поля мастера, а не те, из которых собран цикл) | **P1** |
| 3 | **Нет safety-валидации ручных правок**: в редакторе сессий можно наставить 7×180 мин HIIT (1260 мин/нед) без предупреждения | **P1** |
| 4 | **Степперы недели всегда начинаются с 1**: нет «📍 перейти к текущей неделе» (редактор/предпросмотр) | **P1** |
| 5 | **Таблица недель без пагинации**: 52 недели рендерятся сразу (тормозит на слабых устройствах) | P2 |
| 6 | **Расход ккал не связан с питанием**: kcal/нед отображается, но нет моста в планировщик питания (kind 'cardio' в bridge уже есть, но не используется) | P2 |
| 7 | **Нет медиа-запросов в кардио-компонентах** (таблицы дней/степпер на узких экранах — только горизонтальный скролл) | P3 |
| 8 | Крайние тесты: 104 недели / вес 300 / все 7 дней ног — покрыты частично | P3 |

## 3. План доработки

### Этап G (P0) — `startDate` цикла
- [x] Движок: `CardioCycle.startDate` (локальная дата; по умолчанию — сегодня; миграция — тоже);
      `CardioCycleInput.startDate`.
- [x] UI: CardioProgressCard, шапка «Сегодня»/«до старта», CardioSessionTimer, CardioAutoTunePanel,
      CardioDiaryPanel (adherence) — используют `cycle.startDate` как reference.
- [x] Тесты: startDate неделю назад → неделя 2; по умолчанию — сегодня.

### Этап H (P1) — Снапшот параметров сборки
- [x] Движок: `CardioCycle.config` (снапшот входа) + `configFromCycle`.
- [x] UI: кнопка «⚙️ Изменить параметры» на шаге «Предпросмотр» → загрузка config в мастер
      (шаг 1) и пересборка; config хранит «чистые» параметры (без variant-наложения).
- [x] Тесты: config roundtrip (goal/weeks/days/level/equipment/legDays).

### Этап I (P1) — Safety-валидация правок
- [x] Движок: `cardioSafetyReport` (сессия > лимита: Z2/MISS 90, HIIT 30, recovery 120;
      HIIT > 3×/нед; неделя > 600 мин) — встроен в `cardioQualityReport` (штрафы).
- [x] UI: предупреждения в CardioWeekEditor (под шапкой недели).
- [x] Тесты: перегруз → warn (сессия/HIIT); норма → нет warn; качество штрафуется.

### Этап J (P1) — «📍 К текущей неделе»
- [x] CardioWeekEditor и CardioPreviewStep: кнопка «📍» — переход к неделе по `cycle.startDate`.
- [x] Тесты: клик не ломает навигацию; степпер остаётся валидным.

### Этап K (P2) — Пагинация таблицы недель
- [x] CardioPreviewStep: при >16 недель — показ первых 12 + «Показать все (N)».
- [x] Тесты: 52 недели → кнопка есть; после клика исчезает.

### Этап L (P2-P3) — Ккал→питание + мобильность
- [x] «🔥 Ккал в буфер» на предпросмотре (clipboard + fallback с гарантированным flash).
- [x] `@media (max-width:480px)` для кардио-сеток дней (PreviewStep/WeekEditor): 4 колонки.
- [x] Тесты: буфер-кнопка; пагинация; медиа не тестируется (визуально).

## 4. Критерии готовности
- [x] Прогресс/adherence/«Сегодня» корректны для циклов, собранных ранее;
- [x] Готовый цикл можно доредактировать в мастере без потери параметров;
- [x] Ручные правки не позволяют построить опасную перегрузку (с предупреждениями);
- [x] Быстрый переход к текущей неделе;
- [x] 52-недельный план рендерится плавно (пагинация);
- [x] Расход ккал доступен для планировщика питания (буфер);
- [x] tsc 0, cardio-тесты зелёные (194), `vite build` OK.
