## Диагноз текущей выдачи

Архитектура перевёрнута: `pick из пула → 10 коррекций → свалка`.
Весь интернет делает наоборот: `скелет приёмов с целями → якорные стейплы → точная порция в граммах → 1 финальный кламп`.
Симптомы: геодак/трубач в рационе, овсянка 5×/день на 800 г У (клетчатка 90–120 г), «лосось 374 г»,
«тортилья 374 г», peri-окна рвутся корректорами, рецепты режутся SHRINK_LADDER (пропорции рвутся,
декомпозиция врёт ×3).

## Числа-ориентиры

- Белок: 1.6–2.2 г/кг (сушка/курс до 2.3–3.1 г/кг LBM). За приём 0.40–0.55 г/кг, минимум 4 приёма.
  110 кг → 44–60 г/приём. 500 г/день — только про-режим 130+ кг (Coleman 546 г), обычным — честный варнинг.
- Угли: массонабор 5–7 г/кг, экстрим 8–12 г/кг (ISSN glycogen max). 800–1000 г = 110–130 кг на наборе.
  1200–1500 г = 130+ кг / 6000–7000 ккал / carb-load. Потолок приёма: 80–130 г медленных + до 60 г быстрых в peri.
- Жиры: 0.7–1.0 г/кг, минимум 0.5, 20–35% ккал. На 5000–6000 ккал = 140–200 г. Жиры утром/вечером, ноль в peri.
- Клетчатка: кап 10–14 г/1000 ккал, потолок дня ~50–70 г. База extreme — белый рис/манка/рисовая лапша/
  картофель (0.5–2 г клетчатки/100 г), овощи 200–400 г/день low-FODMAP, peri — 0 овощей.
- Приёмы: до 3000 ккал — 4–5; 3500–4500 — 5–6 (+pre/post); 5000–6000 — 6–7 + intra каждые 2–3 ч
  (post 800–1000 ккал); 6500+ — 7–8 + 2 жидких (70% whole + 30% juice/honey/HBCD).
  Формула: meals = 5 + floor((kcal-3000)/800), кап 7 + intra-слот.

## Новая логика (5 шагов)

### Шаг 1. Скелет дня с целями (NEW, по RP + ETM)
До любой еды — массив слотов с target {p,c,f}:
- трен-день (треня 17:00): завтрак(P25/C20%) → обед(P20/C15%) → pre(P15/C20%, fat≤10) → intra(жидкий C 30–80)
  → post(P25/C25%, fat≤10) → ужин(P15/C15%) → presleep(P slow 30–40, C 0–5%).
- отдых: ровно + акцент углей в первую половину дня.
- Если C/приём >130 или P/приём >65 — делим самый большой слот (обед→обед+полдник). Это авто-6/7 приёмов.
- Слот = контракт ±10%. Сборка обязана его выполнить, не «добрать в конце».

### Шаг 2. Якорное ядро (NEW, по Vertical)
2 белка-якоря + 2 угольных якоря на весь день покрывают 70–80% Б/У
(курица+говядина, белый рис+картофель/манка). Остальное — ротация «1 отличный продукт» на приём.
Вегетарианство/аллергии меняют якоря, не механику.

### Шаг 3. Углеводная лестница плотности (NEW)
Порядок добива углей: белый рис/манка/рисовые макароны → картофель/батат → хлебцы/банан/сок/мёд
(быстрые, только peri+утро) → HBCD/декстроза intra (трен-день, 30–60 г/ч, сессия >75 мин) →
овсянка/греча/бобовые только если клетчатка < капа, иначе запрет.

### Шаг 4. Peri-lock (ужесточить существующий страж)
Pre/intra/post/presleep считаются первыми и лочатся. Все мутации (fixM, баланс, жир-догон,
топ-апы, special-meals, рецептурный путь) — только в гибкие слоты.

### Шаг 5. Сборка «порция в граммах» + выдача как у ETM/MacroFuel
граммы = target / плотность_якоря, сетка (рис 50/100/150/200/250 сухого, мясо 100/120/150/200,
масло 5/10/15). Один финальный проход ±4% — только жирами гибких слотов. Белок/угли после сборки не трогаем.
UI: шапка дня (цель→факт, формула ±X%, клетчатка vs кап), приём = роль + target→fact + 2–4 строки-якоря
+ 1 топ, жидкий слот отдельной карточкой, закупки из якорей (5–8 позиций).

## Пример: 110 кг, 5100 ккал, Б220/Ж110/У800, трен-день
Завтрак Б40/У120/Ж25 (омлет 3 яйца + рисовая каша 120 сух + мёд 20 + банан) →
обед Б40/У110/Ж20 (говядина 170 + рис 150 сух + огурец + масло 10) →
pre Б30/У140/Ж5 (курица 130 + рис 130 сух + сок 300) → intra У60 (HBCD 60) →
post Б50/У170/Ж5 (изолят 40 + манка 120 сух + банан 2 + мёд 30) →
ужин Б40/У130/Ж25 (курица 170 + картофель 500 + овощи + масло 10) →
presleep Б30/У30/Ж15 (творог 200 + йогурт 150 + орехи 15).
7 слотов, клетчатка ~35 г, 0 свалки.

## Внедрение
- P0 — скелет + lock (per-meal targets + peri-lock всех мутаций).
- P1 — якоря + лестница (2+2 якоря/день + carb-density ladder + кап клетчатки как стоп-кран).
- P2 — жидкий слот (intra/шейк отдельным типом, HBCD > мальта > сахар по ЖКТ).
- P3 — порции в граммах (один решатель + 1 жировой кламп вместо каскада коррекций).
- P4 — рецепты-слоты + выдача (роль+плотность у рецепта, UI по слотам, закупки из якорей).

## Дополнение 06.09.2026 — добивка: почему «везде суётся один продукт» и как чинить

### Диагноз механики (по коду)
- Пулы добивки — короткие фиксированные списки: TOPUP_PROTEIN 8 id (chicken_breast, cottage_cheese_5,
  whey_isolate, turkey_breast, beef_lean, casein, egg_whole, tuna_canned), TOPUP_CARB 12 id
  (рис/овёс/греча/картофель/макароны/батат/булгур/хлеб…), TOPUP_FAT 5 id. Выбор — сортировка по
  «макрос/ккал» + bb_quality_score, т.е. детерминированно побеждает один и тот же id
  (булгур/рис/курица). Отсюда «везде суётся продукт добива».
- Граммовка = дефицит / per100 × 100 целиком в один приём, до 80 итераций correctDayToTargets.
  Недобор 300–500 г У на high-carb физически нельзя закрыть одним продуктом в один приём —
  получаются «курица 400 г», «рис 300 г сухого поверх полной тарелки», пинг-понг add/cut,
  дедлоки топ-апа, срезка клетчатки следом (5089→4307 ккал).
- E5 (фрукт) и F1 (comfort) + DENSE_CARB_LADDER уже пытаются чинить, но работают ПОСЛЕ переполненной
  тарелки (>550 г твёрдого — поздно) и конкурируют друг с другом за тот же remC.
- Белковая добивка сывороткой в перекус с бюджетом 15 г давала 30–35 г и системный перебор —
  залечено костылём «добивать творогом», но корень (один продукт на весь дефицит) остался.

### Решение: добивка = коктейль, а не продукт
Принцип: **дефицит > порога съедобности одного продукта всегда закрывается набором 2–4 носителей,
а не наращиванием граммов одного**.

1. **Белковый коктейль добивки** (идея пользователя, верная):
   - Состав: жидкий яичный белок (egg_white_liquid, уже в FOOD_DB: 42 ккал, Б10/100 г, fiber 0)
     + изолят/концентрат (whey_isolate 88 Б/100) + куриное филе / индейка / творог как твёрдое ядро.
   - Логика: до ~30 г дефицита — один носитель (творог/курица 100–150 г). 30–60 г — пара
     (курица 100 + изолят 15–20). 60+ г — тройка (курица 120 + белок жидкий 200 мл + изолят 15),
     распределять по 2–3 приёмам, а не в один. Жидкий белок даёт объём без жевания и жира —
     критично на 300–500 г белка/день.
   - Капы: изолят ≤40 г/приём (уже есть), жидкий белок ≤300 мл/приём, твёрдое мясо ≤200 г/приём.
     MPS-порог соблюдается автоматически, т.к. коктейль идёт в приём с существующим белком.
2. **Углеводный коктейль добивки** (идея пользователя про пряник — верная):
   - Состав: плотный носитель (pryaniki 74У, jam 69У, honey, corn_flakes, cream_of_rice 82У —
     всё уже в FOOD_DB и DENSE_CARB_LADDER) + база (рис/манка) + напиток (сок 400 мл / HBCD peri).
   - Логика: до ~60 г дефицита — один шаг лестницы (пряники 80 г = 60 У без 300 г каши).
     60–150 г — пара (рис +80 г сух + пряники 50 / джем 40). 150+ г — обязательно делить на 2–3 приёма
     + подключать жидкие (сок/HBCD), иначе тарелка >550 г и трим всё срежет.
   - Сахарный потолок уже есть (15% база, 20% при ≥1000У, 25% при ≥1300У) — коктейль обязан его
     уважать: сначала несладкие плотные (corn_flakes/cream_of_rice/хлеб белый), потом сладости.
3. **Правила деления (общие)**:
   - Один продукт — не более 40% остаточного дефицита за одну итерацию; остаток — следующим
     носителем или следующим приёмом (carbMealIndex/flexMealIndex уже умеют round-robin — использовать).
   - Дедуп дня: носитель, стоявший в 2 приёмах, пропускаем (уже есть счётчик _dayUses — распространить
     на все пути, включая products и корректор, сейчас он только в recipe-mode HV).
   - Тарелка-стоп: >550 г твёрдого — добивку в этот приём не льём, идём в следующий (уже есть в F1 —
     поднять на уровень выше, до выбора приёма, а не после).
   - Клетчатка-стоп: добивка только low-fiber (≤3 г/100) при fiber дня >70% капа (фильтр convenientCarbs
     уже есть в recipe-пути — включить везде на HV).
4. **Что не делать**: не наращивать gramsForMacro до бесконечности; не класть декстрозу/сок в обычные
   приёмы (только peri — уже запрещено, держать); не добивать жиры орехами сверх 15 г/приём (уже есть —
     держать); не трогать presleep/intra (уже locked — держать).

### Мини-спецификация коктейлей (к внедрению в P1)
- `PROTEIN_TOPUP_COCKTAIL`: [{id: chicken_breast|turkey_breast|tuna_canned, max 150}, {id: egg_white_liquid, max 300},
  {id: whey_isolate|casein, max 30}] — собирать по дефициту снизу вверх, граммы = min(need, max) каждый шаг.
- `CARB_TOPUP_COCKTAIL`: [{id: cream_of_rice|corn_flakes|bread_white, max по EDIBILITY_CAPS}, {id: pryaniki|jam|honey, max 60/55/60},
  {id: orange_juice (только peri/утро) | dates (≤60), max}] — тот же принцип, sugar-cap проверяется после каждого шага.
- Оба коктейля идут через существующие edibilityCapFor/liveLadderSteps, новых id в FOOD_DB не требуется
  (всё уже есть: egg_white_liquid, whey_isolate, pryaniki, jam, honey, corn_flakes, cream_of_rice,
  orange_juice, dextrose).

### Коктейль = один рецепт (требование 06.09.2026)
Коктейль добивки оформляется как единая сущность-рецепт в приёме, а не россыпью строк:
- `recipeApplied = "🥤 Протеиновый коктейль"` / `"🍯 Углеводный добор"` (+ `recipeAppliedData: {ingredientIds,
  portionScale, kind: 'topup_cocktail'}`), items коктейля группируются под одним бейджем.
- Защита как у рецептов: ядро коктейля не режется корректором/тримом (аналог inCore), масштаб —
  только целиком через portionScale; снятие/замена — одной кнопкой.
- Отображение: одна строка-бейдж с раскрытием состава (как recipeApplied в MealListRender/print/
  briefing/shopping — переиспользовать те же каналы, новых не плодить).
- Назначение видно: rationale «Назначено коктейлем: закрыт дефицит Б +XX г», в брифинге готовки —
  отдельной строкой «🥤 приготовить», в закупках — ингредиенты коктейля суммируются.
- Второй рецепт приёма (recipeApplied2) коктейлем не занимается — слот резервируется под коктейль
  отдельным полем, чтобы не ломать механику двух рецептов.

### Второй рецепт: сделать реальным, а не убирать (требование 06.09.2026)
Диагноз: механика второго рецепта уже есть (`addSecondRecipeToMeal`, авто-второй в
`planner-recipe-mode.ts:1711`, UI `MealListRender.tsx:314-339`, shrinkFirst ⚖️, рескейл ×0.5/1/1.5/2,
убрать 2-й), но в полный рацион он не встаёт: гейт комнаты (`_rawRoom<=0` → тихая мини-порция 150 ккал
+ warning), гейт совместимости (блок вместо предупреждения), авто-второй только при недоборе ≥25%
и цели ≥700 ккал. Редактор цели приёма 🎯 (`MealListRender.tsx:100-118`) пишет в
`he_meal_target_overrides`, но применяется только пост-проходом при следующей генерации
(`IndividualPlanContext.tsx:3248`, инвариант дня ±5%), текущий приём не пересчитывается, ключ —
только label (коллизии между днями). Убирать фишку нельзя: обед 220У одним рецептом не закрыть
(комментарий в коде 1706) — без второго рецепта high-volume recipe-режим вернётся к «корзине».
Решение — чинить, не удалять:
1. Второй = делёж цели приёма, а не «остаток». При добавлении в закрытый приём — явный выбор вместо
   тихой мини-порции: [⚖️ Ужать первый ×0.65] [Забрать из перекусов/гибких] [Отмена]. Уже есть ⚖️
   в пикере — сделать основным диалогом.
2. Совместимость: жёсткие блоки оставить только аллергены/вегетарианство/peri; остальное
   (похожий Б/У-профиль) — предупреждение с кнопкой «всё равно добавить».
3. Peri/presleep/инсулин-окна: запрет второго держать (одно окно = одно блюдо), но с объяснением.
4. 🎯-редактор: применять сразу к текущему дню (рескейл приёма к новой цели + ребаланс дня через
   существующий `rebalanceDayAfterRecipes`), ключ — dayIdx+label, бейдж оверрайда на приёме,
   кнопка сброса. Тогда «КБЖУ приёма редактируется» реально, а не только в localStorage.
5. Коктейль добивки и второй рецепт не делят слот: у коктейля своё поле (см. выше).
