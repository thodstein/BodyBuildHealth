## 3. Пробелы до «хорошего уровня» (не только лёгкий)

### A. Исполнение и дневник (ядро, самое ценное)
- **A1. Кардио-сессии не входят в основной тренировочный дневник**: `he_cardio_sessions` читается только внутри
  кардио-модуля. TrainingDiaryHub/календарь дневника кардио не видят. Нужно: кардио-слой в календаре/истории
  дневника (запись «ZONE2 40м · 🚴»), быстрый вход «▶ Старт» из дневника.
- **A2. Нет суммарной нагрузки дня (сила + кардио)** — комбинированный объём/нагрузка дня не показывается.
- **A3. Нет переноса сессии (reschedule)**: есть «⏭ Пропустить», нет «перенести на другой день» (сессия
  пропускается, но план недели не перестраивается; weekEditor позволяет руками, но в исполнении — нет).
- **A4. План vs факт по неделям не визуализирован**: `cardioAdherenceSummary`/`cardioWeekAdherence` есть,
  `CardioVolumeChart` рисует только план. Нужен график план/факт (мин/нед, % выполнения) и сводка цикла по
  завершении (отчёт: недель выполнено, adherence, сожжено ккал, RPE-тренд).
- **A5. «Сегодня» и следующая сессия не вынесены в общий UI**: прогресс есть в мастере, но на главном
  тренировочном экране/дневнике кардио-виджет отсутствует (LinkCard показывает строку без «▶ Старт»).

### B. Питание
- **B1. Мост ккал → планировщик питания**: `cardioNutritionNotes` — статичный текст; «Ккал в буфер» — ручной.
  Нужен рабочий kind `'cardio'` в planner-bridge: расход кардио (ккал/нед, «сожжено сегодня» из журнала)
  передаётся в IndividualPlan (коррекция целевого дефицита/добавка) — замыкает петлю «цикл → питание».
- **B2. «Сожжено сегодня»**: из `he_cardio_sessions` по дате → в целях дня (карточка в планировщике питания).

### C. Наука тренировки
- **C1. MISS и вариация протоколов**: добавить MISS (Z3) в профили (фартлек/темпо/лесенка 30-45-60),
  чередование в build-фазах — сейчас только zone2/hiit/recovery.
- **C2. Зоны по факту**: журнал собирает `avgHr` — нет анализа «фактический пульс vs targetHr» (перегруз/недобор
  зоны, коррекция зон). Авто-совет: «средний ЧСС выше зоны на N уд — снизьте темп».
- **C3. Кардио в нагрузке/ACWR**: ACWR считается только по силовым sRPE. Опция включить кардио-минуты×RPE в
  нагрузку дня (единый день-фактор для объединённого ACWR).
- **C4. Авто-прогрессия по факту по неделям**: autoTune работает по adherence/RPE, но нет «недельной» версии
  (после 2 «лёгких» недель подряд — предложить +10%, после 2 перегруженных — −10% к следующим неделям).

### D. Персонализация
- **D1. Факторы профиля по умолчанию выключены** (factorsOn=false): сон/стресс/HRV/PED/суставы — только по
  чекбоксу. Нужно: авто-детекция с бейджем «⚠ обнаружено» и включением по умолчанию + подсказка.
- **D2. legDays только ручные**: при подключении к ПЛ/ББ-плану дни ног не определяются из силового плана
  (LinkCard передаёт только ACWR). Нужно: из `buildSrc`/BB-плана определить дни ног → пересборка раскладки.
- **D3. Женский профиль**: ЧССмакс 226-age есть; нет отдельных дефолтов (объём ×0.9, без HIIT до базы) и
  формулировок — мелко, но для «хорошего уровня» желательно.

### E. Интеграции
- **E1. Годовой план**: кардио привязано к макро (cardioCycleId) + слой «Итог года», но нет кардио-блоков в
  annual-training (конструктор «сборка года» не включает кардио-циклы). Ссылка есть — блоки не строятся.
- **E2. Старт-контроль**: перед соревнованием нет «контроля готовности» (вес/восстановление/последняя неделя),
  как в BB-contest-prep (чек-лист). Мини-версия: карточка «🏁 Старт через N нед — вес/сон/готовность».
- **E3. Import/export**: .ics/печать есть; нет импорта сессий (спорт-часы/файл) и экспорта .tcx/.gpx —
  опциональный pro-этап.

### F. UX
- **F1. Одношаговый вход**: сейчас мастер 5 шагов; пресеты есть, но нет «собрал пресет → сразу в дневник»
  (однокликовый флоу для быстрых целей).
- **F2. Пустые состояния и подсказки** — частично есть; добавить подсказку «как пользоваться» в шаге Дневник
  (записать сессию → авто-подстройка → вес).
- **F3. Мобильные сетки**: частично (480px); таблицы недель и степперы — ок после round-3.
