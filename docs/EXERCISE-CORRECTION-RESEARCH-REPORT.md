# Исследование: упражнения и корректировки для движений (Мастер движений)

Дата: 17.10.2026  
Область: `src/engines/lms/weakpoint-pl.ts`, `src/engines/pro/lift-diagnostics.engine.ts`, `src/engines/pro/limiter-calculator.engine.ts`, `src/ui/screens/TrainingScreen_parts/LiftMasterCard.tsx`.

## 1. Что осталось после реализации плана

Не закрыто / частично:
1. **Офлайн-CV**: MediaPipe WASM грузится с CDN; при офлайне — мок. Нужен локальный бандл или честный режим «только ручной ввод» (уже добавлен).
2. **Визуализация бар-патха**: есть SVG-схема и легенда, но нет реального оверлея траектории по точкам (Kinovea даёт xLoop/yMax, но не полную линию в UI).
3. **Двойной сенсор асимметрии**: нет ввода двух наборов L/R скоростей; только ручной L/R и фазовая асимметрия.
4. **Навигация по 10 блокам**: нет якорей/оглавления; экран длинный.
5. **Онбординг**: нет пустого состояния для новых пользователей.
6. **Коррекции/упражнения**: база ассистентов захардкожена; нет обновления по современным данным и нет per-athlete адаптации (например, по длине рук/антропометрии — частично есть).

## 2. Исследование: корректировки слабых фаз (доказательная база)

Источники: NSCA Essentials, JSCR (sticking point studies), Stronger By Science, RTS, BarBend/Powerlifting.com (2024–2026), Kinovea/VBT-практика.

### 2.1 Жим лёжа
- **Сход с груди (off_chest)**: максимальный плечевой момент; слабый старт → пауза на груди 2–3с, жим с пола (dead-stop), наклонный жим на верх груди, отжимания с дефицитом. (Уже в движке.)
- **Середина (mid)**: переход грудь→трицепс; скоростной жим (динамические усилия 50–60%), жим с остановками, жим средним хватом.
- **Дожим (lockout)**: трицепс-доминант; дожимы с досок/плинтов (3/5/8/10 см), жим в раме (дожим), жим узким хватом, французский жим.
- **Антрометрия**: длинные руки → узкий хват (1.0× биакром.), локти 30–45° tucked, акцент трицепс/широчайшие; короткие → шире хват, локти 60–70° flared, грудь-доминант. (Реализовано в anthroHint.)
- **VBT**: velocity loss 10% (скорость), 20% (сила), 25% (масса); MVT жима 0.15 м/с.

### 2.2 Присед
- **Низ (bottom)**: максимальный тазобедренный/коленный момент; пауза в яме, присед на груди, болгарские сплит-приседы, жим ногами.
- **Середина (mid)**: позициональная сила; базовый объём, жим ногами, присед с остановками.
- **Дожим (lockout)**: ягодицы/разгибатели; наклоны (good morning), RDL, присед в широкой постановке.
- **Отклонения**: hips shoot up → присед на груди/пауза; good morning → наклоны/RDL; forward drift → RDL/наклоны.
- **MVT**: 0.25 м/с.

### 2.3 Становая тяга (классика/сумо)
- **Старт (с пола)**: дефицит (тяга из ямы), тяга с плинтов ниже обычного, присед.
- **Середина (колени)**: тяга с остановками, RDL, тяга с паузой ниже колен.
- **Дожим (lockout)**: тяга с плинтов выше колен, RDL, шраги.
- **Сумо**: срыв → широкая постановка/тяга из ямы; замыкание → тяга с плинтов + широкая постановка.
- **MVT**: классика 0.16, сумо 0.16 (ориентир).

### 2.4 Остальные движения (OHP, row, pulldown, incline, biceps, triceps, calf, shrug)
- Угловая диагностика и ассистенты уже покрыты в `weakpoint-pl.ts`/`lift-diagnostics.engine.ts`.
- Рекомендации по изоляции головок (BB-грануляр) добавлены в UI (12 изолятов).
- MVT-ориентиры помечены как оценочные (isEstimate: true) — честно.

### 2.5 Асимметрия
- Пороги Bishop/Parkinson: <10% норма, 10–15% наблюдение, >15% выраженная.
- Коррекция: унилатеральные упражнения (Bulgarian split, single-arm row, dumbbell press) +1 сет слабой стороне, билатеральный объём не повышать при >15%.
- (Реализовано: L/R-ввод, фазовая асимметрия, наклон из Kinovea.)

## 3. Рекомендации по обновлению движка упражнений

1. **Добавить per-athlete адаптацию ассистентов** по антропометрии (уже есть подсказки хвата/локтей; расширить на глубину приседа/стойку тяги).
2. **Расширить каталог ассистентов** современными упражнениями: Spoto press, Larsen press, tempo squats, pause deadlifts, deficit pulls, RDL variations, unilateral work.
3. **Добавить «нагрузку по фазе»**: %1RM для ассистентов (уже есть intensityPct), но сделать зависимым от цели (сила/гипертрофия).
4. **Добавить «негативные» коррекции**: что НЕ делать (например, не использовать читинг, не делать touch-and-go при слабом старте).
5. **Валидация ассистентов через тесты**: проверять, что все имена из assistanceFromCatalog присутствуют в EXERCISE_CATALOG (уже частично).
