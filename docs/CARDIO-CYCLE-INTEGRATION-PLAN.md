# План: отдельный кардио-цикл и интеграция с PL/BB

Статус: [ ] запланировано · [~] частично · [x] реализовано

## 1. Решение по архитектуре

Кардио разрабатывается как самостоятельный цикл, а не как набор полей внутри BB- или PL-цикла.

Общий годовой план содержит связанные, но независимые контуры:

```text
Macrocycle
├── PLMacrocycle
├── BBMacrocycle
└── CardioCycle
```

Причины:

- кардио имеет собственные фазы, объём, интенсивность, частоту и ограничения;
- один CardioCycle можно подключить к PL, BB или общему тренировочному плану;
- кардио можно перестроить без потери выбранных упражнений и циклов PL/BB;
- taper для PL и BB отличается, но использует один кардио-цикл;
- дневник выполнения, ACWR, ЧСС и расход калорий относятся к кардио отдельно от силового плана.

Кардио не должно автоматически пересобираться при каждом изменении силового плана. После изменения PL/BB показывается действие «Пересчитать кардио под новый план» с предпросмотром изменений.

## 2. Целевая модель данных

### 2.1. Типы

```ts
type CardioType = 'zone2' | 'miss' | 'hiit' | 'recovery';
type CardioGoal = 'health' | 'mass' | 'cut' | 'recomp' | 'maintenance' | 'recovery';
type CardioPhase =
  | 'base'
  | 'build'
  | 'maintenance'
  | 'contest_prep'
  | 'taper'
  | 'peak'
  | 'transition';

interface CardioSession {
  id: string;
  type: CardioType;
  dayOfWeek?: number;
  durationMin: number;
  frequency: number;
  intensity: 'low' | 'moderate' | 'high';
  targetHr?: { min?: number; max?: number };
  kcalPerSession: number;
  purpose: string;
  restrictions?: string[];
}

interface CardioWeek {
  week: number;
  phase: CardioPhase;
  sessions: CardioSession[];
  totalMinutes: number;
  totalKcal: number;
  deload: boolean;
  taper: boolean;
  rationale: string[];
}

interface CardioCycle {
  id: string;
  name: string;
  goal: CardioGoal;
  totalWeeks: number;
  weeks: CardioWeek[];
  linkedMacrocycleId?: string;
  linkedCompetitionIds?: string[];
  source: 'auto' | 'manual' | 'imported';
  version: 1;
  rationale: string[];
}
```

### 2.2. Связь с макроциклом

В `Macrocycle` добавляется необязательная ссылка, не копия плана:

```ts
interface Macrocycle {
  // существующие поля
  cardioCycleId?: string;
  cardioMode?: 'none' | 'auto' | 'manual';
}
```

В блоки PL/BB добавляется только профиль контекста:

```ts
type CardioProfile = 'health' | 'maintenance' | 'cut' | 'recovery' | 'taper' | 'peak';

interface MacroBlock {
  // существующие поля
  cardioProfile?: CardioProfile;
}
```

Конкретные сессии хранятся только в `CardioCycle`. Это предотвращает дублирование и рассинхронизацию.

## 3. Движок кардио

Текущий `src/engines/lms/cardio.engine.ts` сохранить как основу, но расширить:

```text
buildCardioPlan()       текущая недельная рекомендация
buildCardioCycle()      полный многонедельный цикл
adaptCardioToStrength() согласование с PL/BB нагрузкой
applyPLCardioTaper()   taper перед PL стартом
applyBBCardioTaper()   taper и peak week для BB
compareCardioCycles()  сравнение сценариев
```

### 3.1. Входные данные `buildCardioCycle`

- цель и уровень спортсмена;
- масса тела и при необходимости целевой вес;
- число доступных дней;
- длительность макроцикла;
- PLMacrocycle и/или BBMacrocycle;
- соревнования и приоритет A/B/C;
- текущая силовая частота и объём ног;
- ACWR, readiness, HRV, сон, стресс и усталость;
- ограничения по суставам и травмам;
- кардиориск, давление и ограничения врача;
- предпочтительный тип оборудования;
- режим: auto или manual.

### 3.2. Фазовые профили по умолчанию

| Контекст | Рекомендация |
|---|---|
| Health/base | Zone 2: 2-3×25-40 мин, recovery по необходимости |
| BB hypertrophy | Zone 2: 2×20-30 мин или recovery 1×20 мин |
| BB strength | Zone 2: 2×20-30 мин, HIIT выключен по умолчанию |
| BB contest prep | постепенное увеличение минут, HIIT только при достаточном восстановлении |
| PL base | Zone 2: 2-3×20-35 мин, не ставить перед тяжёлыми ногами |
| PL strength/peak | сокращение объёма, сохранение лёгкой аэробной работы |
| Taper N-2 | общий объём -20-30%, без HIIT |
| Taper N-1 | 1-2 лёгкие сессии по 15-25 мин |
| Peak/show week | recovery или короткая привычная активность, без утомляющего кардио |
| Transition | лёгкая активность, свободный выбор, восстановление |

Эти значения являются стартовыми профилями, а не медицинскими назначениями. При кардиологических симптомах или высоком риске генератор должен ограничить интенсивность и показать медицинское предупреждение.

## 4. Правила согласования с PL/BB

### 4.1. Расстановка по неделе

Приоритеты планировщика:

1. не ставить HIIT за 24-48 часов до тяжёлых ног;
2. не ставить MISS рядом с тяжёлым deadlift/Legs/Glutes-днём;
3. Zone 2 после верхней тренировки предпочтительнее Zone 2 перед ногами;
4. recovery можно размещать в день отдыха;
5. при двух силовых сессиях в день кардио должно быть после силовой, если нет отдельного указания;
6. ручные дни пользователя имеют приоритет над авто-раскладкой.

### 4.2. Ограничения по восстановлению

```text
ACWR caution       -> HIIT убрать, минуты -15%
ACWR dangerous     -> только recovery/короткая Zone 2, минуты -30-50%
низкий HRV/сон     -> не увеличивать кардио, убрать интенсивные сессии
высокий объём ног  -> ограничить MISS и HIIT
плато веса на cut  -> добавить 10-15 мин Zone 2, не добавлять сразу HIIT
```

Любая адаптация должна записываться в `rationale`, чтобы пользователь видел причину изменения.

## 5. Отдельный кардио-конструктор

Кардио является отдельным равноправным конструктором рядом с PL-авто, BB-авто и ручным конструктором, а не обязательным шагом внутри PL/BB.

```text
Training
├── PL-авто
├── ББ-авто
├── Ручной конструктор
└── Кардио-конструктор
```

Главное место создания и редактирования `CardioCycle` — `CardioConstructor`. Он позволяет:

- создать план без PL/BB;
- сохранить его в библиотеку;
- подключить позже к годовому макроциклу;
- дублировать сценарий;
- экспортировать календарь `.ics`;
- отправить недели в дневник/трекер выполнения.

### 5.1. Поток кардио-конструктора

1. Профиль, цель и ограничения.
2. Горизонт цикла и соревнования.
3. Фазовые профили и недельная прогрессия.
4. Раскладка сессий по дням.
5. Предпросмотр конфликтов с PL/BB или ручной программой.
6. Сохранение, экспорт и подключение к макроциклу.

Параметры конструктора: авто по фазам или ручной режим, Zone 2/MISS/HIIT/recovery, доступные дни, лимиты ЧСС, ограничения восстановления, недельная таблица, предупреждения конфликтов и подключение к PL/BB/ручной программе.

### 5.2. Интеграционный блок в PL/BB

В PL-авто, BB-авто и ручном конструкторе показывается компактная карточка:

- «Без кардио»;
- «Подключить существующий цикл»;
- «Создать кардио-цикл»;
- «Открыть кардио-конструктор»;
- «Пересчитать под этот PL/BB-план»;
- «Отключить кардио».

В силовом плане хранится ссылка, а не копия кардио-недель:

```ts
{ cardioCycleId: 'cardio-2026-01', integrationMode: 'linked' }
```

Изменение PL/BB не пересобирает кардио молча: сначала показывается diff, затем пользователь подтверждает пересчёт.

## 6. PL taper adapter

Новый адаптер не меняет силовой план:

```ts
applyPLCardioTaper(cardio, {
  competitionWeek,
  taperWeeks: 2,
  preserveHabit: true,
});
```

Правила:

- N-2: минуты и частота уменьшаются примерно на 20-30%;
- N-1: только лёгкая Zone 2/recovery;
- HIIT удаляется минимум за 2 недели до старта;
- за 48-72 часа не добавляется новая или непривычная нагрузка;
- при уже активном ACWR-deload повторное агрессивное урезание не применяется.

## 7. BB taper и peak-week adapter

Кардио не добавляется внутрь `applyPeakWeekOverlayToBBPlan`. Используется отдельный адаптер:

```ts
applyBBCardioTaper(cardio, {
  contestPrepStartWeek,
  showWeek,
  peakWeek: true,
  legTrainingWeeks,
});
```

Правила:

- в contest prep объём может расти постепенно, но не одновременно с резким ростом силового объёма;
- HIIT прекращается заранее и не используется в peak week;
- MISS заменяется Zone 2 или recovery при приближении к сцене;
- избегать DOMS, повреждения ног и непривычного оборудования;
- не делать резкий переход от большого объёма к нулю без причины;
- peak week использует только лёгкую привычную активность;
- изменения воды, натрия и углеводов не являются частью кардио-движка и остаются в BB contest-prep протоколе.

## 8. Дневник и обратная связь

Добавить хранилище `he_cardio_sessions`:

```ts
interface CardioLogEntry {
  id: string;
  date: string;
  type: CardioType;
  durationMin: number;
  distanceKm?: number;
  avgHr?: number;
  calories?: number;
  rpe?: number;
  completed: boolean;
  notes?: string;
}
```

Дневник должен показывать:

- выполнено/планировалось;
- минуты за 7 и 28 дней;
- среднюю ЧСС и RPE;
- adherence в процентах;
- расхождение плановых и фактических калорий;
- конфликт с силовыми сессиями;
- рекомендацию снизить/сохранить/увеличить кардио.

Автоадаптация выполняется только после подтверждения пользователя. Исключение: safety-ограничения при опасном ACWR или медицинском флаге могут автоматически убрать HIIT и показать причину.

## 9. UI и сохранение

Предлагаемые ключи:

- `he_cardio_cycles` — библиотека циклов;
- `he_active_cardio_cycle` — активный цикл;
- `he_cardio_sessions` — дневник выполнения;
- `he_cardio_ui_prefs` — фильтры и предпочтения.

Сохранение должно поддерживать миграцию существующего `CardioPlan` в однонедельный `CardioCycle`.

Интеграции:

- planner bridge: `kind: 'cardio'`;
- `MacrocyclePanel`: подключение, отключение и пересчёт;
- PL constructor: интеграционная карточка CardioCycle;
- BB constructor: интеграционная карточка CardioCycle;
- календарь `.ics`: кардио-события с типом и длительностью;
- печатная сводка: кардио по неделям рядом с PL/BB.

## 10. Сценарии пользователя

### BB массонабор

Авто создаёт 1-2 лёгкие recovery/Zone 2 сессии. При слабом восстановлении HIIT недоступен.

### BB contest prep

Кардио-цикл увеличивает Zone 2 по фазам, учитывает тренировки ног и автоматически создаёт BB taper без изменения силового плана.

### PL подготовка к старту

Кардио поддерживается в базе, затем уменьшается вместе с PL taper. HIIT удаляется заранее.

### Общий cardio-only цикл

Пользователь создаёт цикл на 8-12 недель, сохраняет его и позже подключает к PL/BB макроциклу.

### Перенос соревнования

Сдвиг даты перестраивает только фазы CardioCycle, связанные с соревнованием. Ручные исключения и выполненные записи сохраняются.
