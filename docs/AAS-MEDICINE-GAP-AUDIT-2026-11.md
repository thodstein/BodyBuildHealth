# Аудит: чего не хватает приложению про ААС / фармакологию / спортивную медицину

Дата: 2026-11-23. Основание — разведка по коду (`src/core/pharma-*`, `src/engines/*pharma*`, `src/data/ped-*`,
`src/data/lab-*`, `docs/FEMALE_AAS_PROTOCOLS.md`). Ссылки даны как `путь:строка`, каждое утверждение проверяемо
чтением файла. Диапазоны строк — по состоянию рабочего дерева на дату аудита.

Сводка: слой **данных и расчётов сильный** (PK/PD, эстеры, ПКТ-тайминг, органные риски, лаб-нормы, женский слой).
Слабые места — там, где продукт становится **медицинским**: дисклеймеры и гейты, субстанции ПКТ-класса в конструкторе
курса, приверженность оральных препаратов, взаимодействия с рецептурными препаратами, доказательная база у чисел.

## 2. Пробелы по severity

### P0 — безопасность и юридический риск

1. **Дисклеймер живёт на одном экране из шести.** `AAS_MEDICAL_DISCLAIMER` определён в
   `src/data/aas-support-protocols.ts:99–103`, рендерится только в `src/ui/screens/FertilityPCTScreen.tsx:756`.
   На самом табе «Фарма» (`src/ui/screens/PharmaScreen_parts/index.tsx`), в `DosageCalculatorTab.tsx`,
   `CatalogTab.tsx`, `InteractionCheckerTab.tsx` — ни «не является медицинской рекомендацией», ни «не для
   самолечения» (grep по «не является/не назначен/информацион» — 0 совпадений). Пользователь получает числа
   (дозы, мг→мл, AI) без рамки.
   *Проверка:* открыть таб «Фарма» → калькулятор доз → в DOM нет текста дисклеймера.
2. **Нет возрастного гейта и подтверждения «не для соревнований/WADA».** grep `несовершеннолетн|age < 18` даёт
   только БАД-контекст. Для продукта про ААС это обязательный экран согласия при первом входе в фарма-раздел.
3. **Взаимодействия с рецептурными препаратами неполные.** В `pharma-interactions.engine.ts` нет правил
   AAS × изотретиноин (гепатотоксичность + тератогенность), AAS × опиоиды (гипогонадизм, апноэ; упоминание только
   текстом в `FertilityPCTScreen.tsx:1023`), AAS × антипсихотики (только `conflicts: antipsychotics` внутри карточки
   тренболона), AAS × большинство ССРИ (есть лишь трен + ССРИ). В `src/data/drug-drug-interactions.ts` ААС почти нет.
   *Почему P0:* это те комбинации, где ошибка стоит госпитализации, и они частые в реальной популяции.
4. **Коморбидности не входят в модель риска.** `V7RiskInput` (`src/engines/risk-engine-v7.ts:40–73`) принимает
   `labs / course / genetics / nutrition / сон / стресс / алкоголь / курение` — и не принимает диагнозы (ХБП, ХСН,
   апноэ, ГБ, СД2). При ХБП и ХСН дозовые тиры и пороги HCT/АД должны меняться, сейчас — нет.

### P1 — клиническая полнота продукта

5. **ПКТ-препараты нельзя добавить в курс.** Классы `pct_serm`, `pct_aromatase`, `pct_dopamine`,
   `pct_gonadotropin`, `peptide_gnrh` описаны в `src/core/pharma-db/class-defaults.ts:20–24`, но отсутствуют в
   `PHARMA_CLASSES` (`src/core/pharma-database.ts:64–69`) и нет самих веществ (тамоксифен, кломифен, энкломифен,
   анастрозол, летрозол, эксеместан, каберголин, hCG). Следствия: ПКТ существует как отдельный текстовый план
   (`pct-planner.engine.ts`), но не как часть курса; доза AI — только текстовое правило
   `src/engines/tz-mapper-engine.ts:854–861`; калькуляторов доз SERM/AI/hCG нет.
6. **Приверженность покрывает только инъекции и БАДы.** Оральные ААС (метандиенон, оксандролон, станозолол,
   туринабол, супердрол), SERM/AI/hCG не имеют ни дневника приёма, ни напоминаний, ни «пропустил таблетку».
   `pharma-reminders.ts` умеет только недельные инъекции (и только в APK).
7. **Конструктор курса беднее модели PK.** `CourseEntry` (`src/core/types.ts:458`) не знает эстер, фазу приёма и цель
   курса; `pharmacology.engine.ts` считает недельный болюс и не использует `injectionDays` (types L467) —
   PK-кривая расходится с реальным расписанием уколов (E3D, EOD, 2×/нед).
8. **Нет калькуляторов: фронт-лоад / ТЗТ-доза / hCG-доза.** Фронт-лоад в репозитории есть только гликогеновый
   (`bb-contest-prep.engine.ts`); ТЗТ — текст в `FertilityPCTScreen.tsx:623–1046`; hCG — доза только внутри
   ПКТ-плана. «Когда сдавать анализ после инъекции» есть только как `bloodworkAfter` в ПКТ-таймере.
9. **Спортивные референсы не покрыты.** В лаб-слое нет отдельных полос для TT > 1500 нг/дл, IGF-1 по возрасту
   (есть порог 100–400), ПСА по возрасту. Для курсового пользователя обычные «нормы» вводят в заблуждение.

### P2 — доказательность и глубина

10. **У чисел нет источника.** Ни у субстанции, ни у порогов нет поля ссылки на исследование: доказательность
    живёт только текстом в `risks[]`, а `evidenceLevel` есть лишь в `symptom-solver.data-part1/part2.ts`. Для
    медицинского продукта нужен `sources: [{pmid|doi, grade}]` хотя бы у доз, t½ и порогов.
11. **Нет периода обнаружения (допинг), рецептурного статуса, стоимости курса.** Поля отсутствуют в
    `PharmaSubstance`.
12. **Нет библиотеки протоколов курсов.** Все «циклы» в `src/engines/cycle*.ts`, `lms/`, `bb/` — тренировочные.
    Blast & cruise, титрация/пирамида, «мост» как объект модели отсутствуют.
13. **Тесты смещены в тренировочный слой.** Без прямых тестов: `src/engines/risk.engine.ts` (22 КБ,
    `calculateRisks` L229, `calculateAggregatedRisks` L423), `injection-diary-integration.ts`; слабо покрыты
    `pct-planner.engine.ts` и `interactions-calculator.ts` (~20 КБ на один файл тестов).

### P3 — структура знаний

14. **Нет единого документа «AAS-медицина»**: правила размазаны по `docs/FEMALE_AAS_PROTOCOLS.md`,
    `src/data/support-*`, `symptom-solver`. Новый участник (человек или агент) не находит точку входа.
15. **Реестр исследований не используется в продукте**: ClinicalTrials.gov доступен агенту через `webfetch`, но в
    приложении нет ни одного места, где показан статус исследования по препарату.

## 3. Что делать (порядок работ)

**Этап 1 — рамка безопасности (P0).** Один компонент `MedicalDisclaimer` + обязательный consent-экран при первом
входе в фарма-раздел (возраст, «не назначение», «не для соревнований», РФ-контекст). Вставить на таб «Фарма» и во все
калькуляторы. Закрывает п.1–2, проверяется DOM-тестом на наличие текста в каждом субтабе.

**Этап 2 — взаимодействия и коморбидности (P0).** Добавить в `pharma-interactions.engine.ts` правила
AAS × изотретиноин / опиоиды / антипсихотики / ССРИ-класс; расширить `V7RiskInput` диагнозами (ХБП, ХСН, апноэ, ГБ,
СД2) и завести их в дозовые тиры. Каждое правило — с тестом и уровнем доказательности.

**Этап 3 — ПКТ как часть курса (P1).** Ввести вещества SERM/AI/hCG/каберголина в `PHARMA_DB` и `PHARMA_CLASSES`,
связать `pct-planner` с `CourseEntry`, добавить калькуляторы доз AI/SERM/hCG и дневник орального приёма
(та же инфраструктура, что у инъекций: расписание, пропуски, напоминания).

**Этап 4 — PK по реальному расписанию (P1).** `CourseEntry` получает эстер и дни инъекций, `pharmacology.engine`
начинает их использовать; добавить фронт-лоад, ТЗТ- и hCG-калькуляторы.

**Этап 5 — доказательная база (P2).** Поле `sources: [{pmid, doi, grade}]` в `PharmaSubstance` и в порогах
`lab-tier-ranges.ts`; заполнять через `research`-скилл (PubMed/OpenAlex), грейд — по иерархии из скилла. Плюс
период обнаружения и рецептурный статус.

**Этап 6 — тесты (P2).** `risk.engine.ts`, `injection-diary-integration.ts`, `pct-planner.engine.ts`,
`interactions-calculator.ts` — по одному файлу на движок, с кейсами на границы порогов.
